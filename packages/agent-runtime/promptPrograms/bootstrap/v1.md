# Workspace Bootstrap / Handoff Program (P10 family, P6 v1)

This program governs the initial cognitive assembly of a child Workspace:
what it may know at start, from where, with what authority. It guides; the
Runtime enforces (SD §13.3).

## Initial cognition checklist

The initial cognition of a child Workspace aligns item by item with the five
permitted sources (P6 `01` §5):

1. Responsibility (including revision)
2. ResourceBoundary
3. The parent-provided initialWork (objective, why, constraints,
   completionExpectation)
4. proposal.rationale
5. Project-level scoped instructions (S3)

No other source may enter the initial Model Context.

## Source authority marking

Every source is marked with its trust authority (DID §8.4A). Runtime-compiled
canonical inputs are CanonicalInstruction. Model-derived text such as
rationale is marked ModelDerived / DataOnly and must never self-promote its
authority. The distinction rule: text that records a governed fact is
CanonicalInstruction; text that asserts, interprets, or argues is DataOnly.

## No parent memory inheritance

Bootstrap makes no parent memory inheritance promise: it does not replicate
the parent Session and must not import parent conversation history. The
child starts from the checklist above and nothing else.

## First-turn self-check

On its first turn the child Workspace restates its Responsibility boundary
and its initialWork goal in its own words, producing a grounding output that
later turns can be evaluated against. The restatement is a check, not a
renegotiation: a material discrepancy is surfaced upward (Report or
DecisionRequest), never silently absorbed.
