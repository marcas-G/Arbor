# Responsibility Formation Program (P5 family, P6 v1)

This program governs the behavior protocol for forming responsibility
division proposals: when splitting work into child Workspaces is justified,
and how to shape the proposal. It guides; the Runtime enforces (SD §13.3).
No instruction below is the sole line of defense for any hard invariant.

## Formation criteria

Propose a child Workspace only when the split is justified by the five
criteria (S1.4 step 3):

1. Independence — the candidate responsibility pursues an outcome that can
   be advanced and verified without continuous coordination with the parent.
2. Parallel value — running it concurrently yields real value over serial
   completion inside the current Workspace.
3. Context isolability — the candidate's information need fits a resource
   boundary that can be isolated without starving either side.
4. Working-style difference — the candidate benefits from a distinct cadence,
   method, or model configuration.
5. Single-agent cost — pursuing it inside the current Workspace would
   measurably degrade the active Responsibility.

A candidate that fails these criteria stays as ordinary work inside the
current Workspace.

## Proposal output structure

Every proposal is a ChildWorkspaceProposal, field for field: name,
responsibilityDraft, resourceBoundaryDraft, rationale, initialWork. The
rationale must argue from the criteria above. When the outcome requirement
is already known, initialWork carries objective, why, constraints, and
completionExpectation; otherwise it is omitted rather than guessed.

## Human gate at the first layer

First-layer proposals must anticipate the human gate: a human decides on
every first-layer division proposal before it takes effect. This program
never claims that the first layer of division is completed by the proposing
agent alone — first-layer legitimacy comes only from the human decision,
never from the proposal itself.

## Deeper subdivision autonomy

Below the first layer, deeper subdivision is the proposing Workspace's own
judgment within its granted authority: it may do the work itself, delegate
serially, or delegate in parallel (the S1.3 three branches), applying the
same formation criteria and respecting its own resource boundary.

## Forbidden clause

This program must not substitute formation for Dependency: dependency
declaration and dependency satisfaction belong to the P7 surface, and this
text makes no promise about either. Never present a formation proposal as a
dependency resolution mechanism.
