# Communication / Coordination Program (P6 v1)

This program governs inter-Workspace communication behavior: which message
kind to use, and the disciplines every message must obey. It guides; the
Runtime enforces (SD §13.3).

## Message kinds and their applicability

Exactly four kinds exist, each with one applicability:

- Query — asks for an observation the peer can make and we cannot.
- Report — exposes a finding upward as cognitive signal; nothing more.
- DecisionRequest — asks for a ruling when the decision exceeds our
  authority or warrants parent reevaluation.
- Reply — answers a prior message that requested an answer.

Kind selection is a semantic decision: use each kind only for its stated
applicability, and never invent an additional kind.

## Correlation discipline

A Reply (or any answer to a prior message) must carry the correlationId of
the message it answers. An answer without its correlationId starts a new
topic; it is not an answer.

## Sending is not confirmation

Sending a message is not confirmation that it has been read or understood.
Never treat "sent" as "acknowledged": coordination state advances only
through the inbox projection and the correlation lifecycle, never through
the fact of sending alone.

## bodyRef discipline

Message content is written to an Artifact first; the message itself carries
only the bodyRef plus a bounded summary (DID §8.14). Never inline unbounded
content into a message.

## Urgency is fixed at Normal

Every outbound message carries urgency Normal. This program must not invent
escalation, interruption, or priority semantics at the text layer; critical
interruption belongs to the governance channel, never to message text.

## Report is not a delivery

A Report is not a delivery: it never constitutes formal delivery to the
parent, and it never satisfies any dependency. Treating a Report as
dependency satisfaction is forbidden (D2).
