# 本机数据备份与恢复（Linux）

此入口备份 Arbor 普通安装的数据库、内容文件和项目目录登记。使用 SQLite 官方
在线备份 API 读取已提交状态，并用现有跨进程维护锁排除运行中的 Arbor。
不执行数据库升级，只接受当前内部格式。

## 备份

先停止使用同一数据库的 Arbor。备份目标必须尚不存在，父目录必须已经存在：

```bash
arbor stop
arbor backup --to "$HOME/arbor-backup-2026-11-15"
arbor verify-backup --from "$HOME/arbor-backup-2026-11-15"
```

如果启动时指定过 `--data-dir`，停止和备份时也使用同一选项；如果指定过非默认
端口，停止时也提供该端口。维护锁会检查实际进程持有的数据库锁，不会只信任 PID 文件。
锁被占用时命令失败，已有目标目录不会被覆盖。失败后没有有效 `backup.json`
的目录不能作为完整备份使用；重新尝试时选择另一个尚不存在的目录。

备份包含：

- 数据库中的项目、工作、对话、审批、验证和恢复记录；
- 数据库旁 `.blobs` 中的全部合法内容文件；
- 历史记录仍引用、且仍存在于旧临时目录中的内容；只读取必要文件，不搬走原件；
- 数据库旁 `.project-directories` 中的目录登记。

每个文件均记录字节数和 SHA-256；校验还会检查 SQLite 完整性、外键和已识别的
内容引用是否齐全。摘要用于发现遗漏和损坏，不提供签名或可信来源认证。

## 恢复

保持原实例停止，恢复到一个尚不存在的新目录：

```bash
arbor restore --from "$HOME/arbor-backup-2026-11-15" \
  --data-dir "$HOME/arbor-restored-2026-11-15"
arbor start --data-dir "$HOME/arbor-restored-2026-11-15"
```

恢复不会覆盖原数据库，也不会升级它。旧执行进程的租约会失效，租约代数前移，
下次普通启动再执行既有恢复流程。中断的恢复目录保留未完成标记，普通启动会拒绝使用。

`--data-dir` 指定的目录不会自动成为启动器的新默认目录；以后继续使用恢复后的数据，
仍需指定它。当前入口属于手动维护功能，没有设置页备份按钮或自动备份计划。

## 需要单独保留的内容

项目源码、未提交改动、Git 仓库与 worktree 不在此备份中。项目目录登记保存的是
原来的绝对路径；换机器或移动项目后不能假装原路径仍然有效。应分别保存项目文件，
不要同时运行指向同一项目文件的原实例和恢复实例。

模型配置、密钥、环境变量以及单独配置的沙箱授权、高水位、审计和资格文件也不在此
备份中。恢复到新机器后需重新配置真实模型；缺少授权文件不等于获得原权限。
此入口面向普通安装默认的数据库旁内容目录，未资格程序化自定义 `blobRoot`。

已经从旧临时目录删除的内容无法凭引用重新生成，备份会因缺失的实际内容引用失败。
环境快照中不是内容地址的引用标记只会原样留在数据库，并单独报告数量；备份不声称
保存了这些标记对应的字节，也不能替代项目源文件备份。
