# 用户选择项目目录

日期：2026-11-11  
状态：用户已要求继续接入；2026-11-12 实现已通过目录选择、文件读取/独立验证、重复打开和重启保留的浏览器旅程。  
接受依据：当前会话先提出自由选择目录及已有项目操作需求，审阅目录选择方案后，用户明确指示“继续接入”。本记录不假定存在会话之外的授权。

## 已接受的产品行为

1. 用户可以输入或浏览 Arbor 服务所在机器的目录，打开已有文件夹，或者在已有父目录下创建文件夹及项目。已有内容不被覆盖。
2. 已有项目显示实际绑定目录，提供打开、继续对话、复制路径及项目管理入口。再次选择同一真实目录时打开原项目，归档项目只查看历史。
3. 目录选择在运行中生效，不要求修改启动环境或重启。项目路径和原有工作历史在重启后保留。
4. 现有目录所有权、文件工具边界、审批、独立验证和人工验收继续约束后续执行。
5. 暂不绑定文件夹仍可通过次要选项显式创建，不自动把无效目录降级为仅对话。

## 对应实现合同

- 本地单用户范围沿用 `user:local`；配置认证时先认证，其他 principal 不能浏览或登记目录。目录浏览及准入是 host bootstrap 操作，不是模型工具或资源权限授予。
- 新增 `/project-directories`：GET 读取规范目录及子目录；POST 接收 `{path, create}`，验证/必要时创建最后一级目录，再持久登记该用户确认的规范路径。POST 要求认证头、JSON 和同源 Origin（如果存在）。
- 新登记使用 `directory-<sha256(principal + NUL + canonicalPath)>` 引用和 `v1` 版本。每个目录的本机登记是不可变文件，存于数据库旁的 `.project-directories` 目录；目录 0700、文件 0600，完整写入并同步后原子发布。此登记属于 host 配置，不新增业务数据库 schema，也不授权升级保留库。
- Application 仍通过 `ProjectResourceProfilePort.resolve` 做无文件系统 I/O 的内存查询。启动预设不变，已登记目录在启动加载，并在成功持久登记后以追加方式加入当前 host 内存表；同一引用不允许更换路径。
- CreateProject 保持 wire-v1 / semantic-v2 载荷和回执规则；创建请求仍只提交引用与版本，不提交 ResourceBoundary 或原始路径。新登记引用在创建写事务中检查是否已经被任一项目根边界绑定；重复绑定返回不包含路径的 `ProjectResourceUnavailable`。预设 Profile 的历史激活冲突语义不变。
- 准入阶段识别已有项目；并发竞争的最后防线是创建事务中的目录绑定检查。旧回执重试仍先回执后查目录；网络失败保留同一创建载荷和命令身份，不用当前目录状态替代历史结果。
- `/projects` 在当前本机单用户目录能力启用时，可额外提供从持久根 Workspace 边界读取的 `directoryPath`。无文件边界返回 null，不从 Profile 名称或当前启动目录猜测。原 `/project-resources` 仍是无路径的兼容预设列表，新增可选能力标记。
- 目录激活继续在创建提交后收敛；已检测到的目录失效及所有权冲突沿现有 Attention 及恢复机制处理，不声称创建已回滚，不切换路径。准入时使用 realpath，别名重新指向其他目录不会改写旧登记；本次不声称能够检测之后发生的所有文件系统替换。新建空文件夹在项目提交失败后保留，重试可复用。

## 所有者落地范围

场景由 `docs/design/01-scenarios.md` 的目录选择增补拥有；host 准入、持久边界和权限分离由 `02-system-design.md` 的增补拥有；精确接口及兼容由 DID §4.1D 与 P1/P12 对应增补拥有。Problem & Goals 的目标不变。

这份记录及拥有者增补的哈希、验证及一致性检查另记于同目录的落地复核记录。新增目录仅在接收准入的当前 host 内存中追加，其他已经运行的 daemon 不保证同步获得它；不声明多 daemon 的动态目录配置一致性。
