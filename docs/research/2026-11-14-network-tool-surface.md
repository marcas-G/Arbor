# 网络工具与扩展入口矩阵

更新：2026-11-15（补充续查与当前源码状态；旧证据保持其采集时点）

本文把 `websearch`、`fetch`、浏览器、MCP、供应商托管工具和后台请求放回真实
使用链路中。它是调研和需求分解，不是新的冻结设计，也不表示下表的能力已经
在 Arbor 中实现。当前负责人已经确定的前提只有：Linux 首发、本机单用户、
严格隔离、必须联网、使用真实模型，并完成真实 coding agent 闭环。

## 先区分五个网络位置

“这个功能能联网”必须先说明请求在哪个位置发出。下面五个位置的网络边界和
凭据不能互相继承。

| 位置 | 典型请求 | Arbor 当前事实 |
| --- | --- | --- |
| Arbor 受信服务 | 模型 API、未来的 `websearch`/`fetch`、权限和状态服务 | 真实模型调用已有路径；网络 broker 候选未接入生产 |
| Linux 隔离执行环境 | npm/pnpm/pip/Cargo/Go、git、curl、构建、测试、项目启动服务 | Native POSIX 生产资格仍未启用；项目命令尚不能作为已交付能力宣称联网 |
| 用户浏览器 | 打开 Arbor UI、查看项目预览、接收热更新 | Arbor UI 的本机连接已有校验；项目预览入口尚未形成发布资格 |
| 扩展或远程服务 | MCP HTTP/SSE/WebSocket、远程 API、远程 worker | 没有可用的 MCP/远程工具产品路径；通用注册接缝不等于已支持 |
| 模型供应商侧 | 供应商代为搜索网页、浏览网页或运行代码 | 请求发生在第三方；本机 broker 不能逐连接约束它，必须单独披露数据和费用 |

例如，模型 API 请求成功，只能说明 Arbor 的受信服务能访问模型；它不能证明
隔离环境能安装 npm 依赖，也不能证明 `fetch`、浏览器或 MCP 可以访问同一地址。

## 按工具拆开的真实网络矩阵

| 能力 | 谁发起、访问哪里 | 发送的数据和凭据 | 可能的副作用 | 首发必须证明的行为 | 当前状态 |
| --- | --- | --- | --- | --- | --- |
| 模型调用 | Arbor 受信服务访问用户配置的 Provider | 对话上下文、获准项目内容、模型配置；Provider 专用密钥 | 产生模型输出和费用，可能触发模型侧工具 | 真实连接检查、流式输出、工具调用、失败分类、停止和重启恢复 | 配置、真实回复和历史重启已有局部验收；完整 coding 闭环未通过 |
| `websearch` | Arbor 受信服务访问明确的搜索 API | 查询词、筛选条件；搜索服务密钥或用户配置的账号 | 查询费用、额度消耗；返回结果不等于已读取目标网页 | 显示真实 provider 和来源；无密钥、限流、失败和取消可解释；结果 URL 后续仍重新检查 | 当前没有内置工具、执行器或生产权限合同 |
| `fetch` | Arbor 受信服务通过 broker 读取用户或 Agent 指定的 HTTPS URL | URL、必要时明确的请求头；默认不带网页登录态或主机凭据 | 读取可能有追踪、计费或动态内容；网页内容只能作为不可信资料 | 每个重定向重新做目标检查；拒绝主机/内网/本地文件；限制类型、大小、时间和内容上下文；停止后连接关闭 | 当前没有内置工具；底层 GET broker 只是候选实现 |
| 浏览器自动化 | 隔离的浏览器进程访问页面及其子资源 | URL、页面交互数据；独立浏览器会话凭据 | 表单提交、上传、发布、支付、删除等远程修改 | 导航、脚本、iframe、字体、WebSocket、worker 和下载都在边界内；登录态不继承主机；有副作用的操作单独确认 | 当前只有用户浏览器访问 Arbor UI 的路径，没有 Agent 浏览器工具 |
| 项目命令 | 隔离执行环境访问包仓库、Git、项目 API 或同沙箱服务 | 命令参数、项目文件；项目范围凭据，不是整个 HOME/SSH agent | 下载、构建脚本和测试可能执行代码或修改远程服务 | 真实 npm/git/curl、构建、测试、停止和重启；主机文件、主机服务、内网、其他沙箱和直连绕过失败 | Native POSIX 未获得 production Supported tuple |
| 用户项目预览 | 用户浏览器访问被 Arbor 映射的项目端口 | 页面资源和用户浏览器请求 | 页面自身可能继续请求第三方；可能暴露项目数据 | 只暴露选定项目/端口，支持热更新所需 WebSocket，不把沙箱所有端口开放给局域网 | 需求已登记，发布级入口未完成 |
| MCP stdio | Arbor 启动本机扩展进程，或让隔离环境启动它 | 工具输入、扩展配置和明确注入的凭据 | 扩展可以读写文件、联网或产生远程副作用 | 进程必须有同等隔离、文件和网络边界；停止能结束整棵进程树；工具清单变更不能自动扩大授权 | 当前未提供 MCP 产品路径 |
| MCP HTTP/SSE/WebSocket | Arbor 或受信 connector 访问远程 MCP 服务 | 工具调用、服务地址、服务专用认证 | 远程服务可能已经执行写入，即使本地连接随后超时 | 服务级和工具级授权分开；记录执行地点和目标；超时后先查询/对账，不盲目重发写操作 | 当前未提供 MCP 产品路径 |
| 供应商托管工具 | Provider 在其基础设施访问搜索、网页或代码环境 | 发送给 Provider 的上下文、文件和工具参数 | 费用、第三方数据保留和远程修改发生在 Provider 侧 | UI 和记录明确标为 Provider 托管；不能把它当成本机隔离工具的安全证据 | 当前没有 Arbor 级统一披露和资格矩阵 |
| 后台维护请求 | Arbor、安装器或扩展发起更新检查、诊断、遥测或目录请求 | 版本、错误摘要、可选统计；不得默认发送源码、密钥或对话 | 用户未主动发起的外部通信、费用和隐私影响 | 有明确开关、数据说明、目标清单、取消和失败表现；默认不发送额外内容 | 尚未形成发布级清单 |

## `websearch` 和 `fetch` 不能合并成一个“网页权限”

搜索服务和搜索结果中的网站是两个目标。允许查询搜索 API，不等于允许访问
结果里的每个 URL；搜索结果可能包含主机名、内网地址、恶意重定向或需要登录的
页面。后续 `fetch` 或浏览器导航必须重新执行 URL、DNS、IP、TLS、重定向和凭据
检查。

`websearch` 的最小可审计结果应保留 provider、查询范围、结果 URL、标题/摘要、
时间和请求状态；不要把模型记忆写成搜索来源。查询可能包含项目名、错误信息或
代码片段，用户需要知道这些数据会发送给哪家搜索服务。

`fetch` 的最小安全边界应包括：只接受明确支持的协议；解析和连接都拒绝 loopback、
私网、链路本地、保留地址、主机接口和未知的 DNS 答案；每次重定向重新检查；
限制响应类型、大小、时间、并发和输出上下文；把 HTML/JSON/PDF 内容当作不可信
资料，不把其中的指令自动提升为 Arbor 权限。`file://`、代理环境变量和网页登录
态不能成为绕过文件或凭据边界的路径。

## 浏览器、预览和网页读取是三种不同功能

1. **用户查看 Arbor UI**：用户浏览器访问本机 Arbor 服务，属于产品控制面。
2. **用户查看项目预览**：用户浏览器访问隔离环境中运行的项目，属于受控入站
   映射；热更新可能需要 WebSocket。
3. **Agent 操作外部网站**：隔离浏览器访问第三方页面，属于工具网络和可能的
   外部副作用。

一次静态 `GET` 成功不能证明另外两种功能。动态页面还会发出脚本、iframe、字体、
worker、WebSocket、下载和表单请求；其中上传、提交、发布、支付和删除必须单独
处理。浏览器工具不能继承用户主机的 Cookie、密码库、SSH agent、下载目录或任意
文件选择能力。

## MCP 和供应商托管工具的特殊点

MCP 连接成功只证明“能找到一个服务”，不证明服务中的每个工具都被允许。需要
分别记录服务身份、传输类型、工具名、参数范围、账号、目标资源、是否读写以及
清单版本。服务新增一个写工具时，不能因为原来允许读取就自动放行。

stdio 扩展仍是进程执行，必须进入和项目命令相同的隔离、文件、网络、停止和
恢复管线；不能在 Arbor 受信进程里直接 `spawn` 一个拥有主机环境的扩展。远程
HTTP/SSE/WebSocket 扩展的代码在远端执行，本地只能约束连接、发送数据、工具
选择和本地记录，不能把远端执行当作本机沙箱资格。

供应商内置搜索、网页读取或代码执行也不能与 Arbor 的本机工具混写。必须显示
执行地点、发送给谁、使用什么账号、是否计费和结果来源；Provider 侧发生的远程
副作用不应被本机“停止”按钮假定为已经撤销。

## 共用的请求生命周期

无论是本机工具还是扩展，都应沿用同一套可观察生命周期：

1. 记录工具、项目、目标、凭据范围和请求参数摘要；敏感值只存引用或脱敏摘要。
2. 在实际连接前执行目标和权限检查，不能只在 UI 中显示允许。
3. 为 DNS、连接、响应、子进程和长连接设置超时、大小、并发和取消边界。
4. 把“未发出”“读取成功”“结果已取回但尚未保存”“可能已经发生远程修改”
   分开记录。
5. 停止时取消请求、关闭 socket、结束子进程和浏览器页面；无法撤销的远程写入
   必须显示为未知并要求对账。
6. 重启后安全读取可以重试；带副作用的写入只能依据幂等身份、服务查询或人工
   决策恢复，不能因为上次本地没有收到响应就自动再发一次。

现有 Tool Runtime 已有审批、fencing、观察和 settlement 管线，但没有为上述
网络工具提供工具定义和生产执行器。现有网络候选只证明了部分 HTTPS GET 编排和
Unix socket/TLS 通道，不能替代这些工具的生命周期资格。

## 现在能下的结论

- “需要网络”已经足够确定为产品前提；不需要再选择断网或无隔离模式。
- 具体首发工具范围仍不能从 OpenCode/Cline 的做法自动推导出来。
- 无论负责人最后选择哪些工具，工具都必须进入现有 Tool Runtime、权限、隔离、
  取消、观察和恢复链路，不能用受信进程里的临时 HTTP 请求绕过它们。
- 在工具范围和网络入口合同明确前，不能把当前的局部网络测试写成“完整 coding
  agent 已联网可用”。
