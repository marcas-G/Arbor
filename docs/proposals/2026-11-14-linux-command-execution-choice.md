# Linux 命令执行：需要负责人选择的产品边界

状态：已被负责人澄清取代，保留提问经过；方案 A 不采用，方案 B 的断网
前提也不采用。2026-11-14 负责人明确要求“严格隔离模式，然后需要网络，
不能断网”。当前工作按严格系统隔离加受控联网推进，未启用生产进程能力。
文件任务已完成真实安装包闭环；命令、构建、测试仍是独立发布阻断。

## 已确认的事实

- 负责人要求 Linux 本机单用户 coding agent，命令、构建和测试属于首发。
- 现有首发冻结合同只允许 Disabled 或精确资格化 Native 模式；初始候选是
  Windows 的只读、断网组合。当前 Linux 正式装配没有受信可用组合。
- 较早设计另有“明确选择的 TrustedLocal”语义，但现有首发合同明确禁止
  将它作为正式 shell 路径；当前只能在显式测试装配中使用。
- Linux systemd+bwrap 执行候选已经有定向证据，尚未达到安装包中的完整
  进程执行资格。仅发现系统安装了这些程序不能自动宣布隔离成立。
- 用户授予文件修改权限不会自动授予命令执行，也不能覆盖上述运行模式。

因此，问题不是模型没有接上，而是首发命令采用哪一种真实权限边界。
以下两条路都必须完成真实命令、错误、停止、重启及独立验证，不能直接
暴露测试开关或把 fake Provider 用作产品模式。

## 历史方案 A：用户明确授权的本机命令模式（未接受，已放弃）

面向信任本机项目并希望运行构建、测试、包管理器的主要用户。

固定的产品语义：

1. 普通启动仍不自动运行命令。用户在界面明确选择本机命令模式并确认
   当前项目的命令权限，随后才显示 shell 能力。
2. 命令以当前操作系统用户身份运行，起始目录是所选项目；它不提供操作
   系统级文件或网络隔离。程序可以访问该用户有权访问的其他路径及网络，
   包括开发依赖下载。界面必须在授权前准确说明这点，不能称为“项目沙箱”。
3. 授权绑定当前分工、操作、目标及有效期。它不自动授予其他分工的权限，
   不提升系统权限、不使用 sudo，也不绕过独立敏感动作审批。
4. 文件工具仍使用既有逻辑资源边界。该限制不被冒充为 shell 的 OS 隔离。
5. 显式本机模式与严格隔离模式分开；严格隔离失败不能自动回退成本机模式。
   未选择、配置无效、主体不匹配或授权过期时均不创建进程。
6. 真实超时、输出上限和停止必须结束整个所属进程树，并确认退出后再
   结算。当前本机候选只使用 execFile 的 timeout，不足以证明这条合同，
   必须先修复，不得直接将测试路径改为正式可用。
7. 进程 effect 不确定时保留既有 OutcomeUnknown/Attention，禁止盲重放；
   不因本机模式削弱 P4 的持久 intent、审批、fencing、结果及恢复规则。
8. 模式变更必须经明确本机用户操作，受 Host/Origin 和 JSON 限制；在
   当前没有活动工作时受控重载，不在模型调用期间静默切换。只有准确的
   host 配置面和既有领域命令可以写入，不增加任意配置编辑或通配权限。

接受后，以上八条作为同一固定治理包落入 System Design §11.6 和 Native
addendum、DID 首发 process-mode addendum、P4 `01/02/04/06/08`、P12
`10/13/14` 和 P13 `01/06` 的对应职责。启动模式增补
`TrustedLocalApprovedOnly`，保留 Disabled 的缺省拒绝、Native 的精确资格
和旧记录重放语义。使用既有显式 TrustedLocal policy，不新增数据库迁移。
host 配置面限定为 GET/POST `/process-setup`：读取当前模式与安全的可用性
诊断；写入仅接收 `{mode:"Disabled"|"TrustedLocalApprovedOnly"}`，
拒绝任意其他字段、远程来源或有活动 Execution 的变更，保存后受控重载。
Native 模式的管理保留现有受信配置来源，不由该端点生成资格。
P13 仅为该精确 host 路径增加例外；业务修改继续经 `/commands`。

上述落点是接受后需要做的文档和实现工作，不是当前已经提供的能力。
记录方案摘要、接受记录、逐文档修订和落地一致性审查后才实现。

## 历史方案 B：严格隔离但默认断网（断网前提未接受）

采用 `2026-11-14-linux-native-process-release.md` 中的 Linux 可写项目、
默认断网候选，并先完成全部受信资格及普通安装包装配，再开放命令。
无资格时不给命令权限，也不回退为本机进程。

该方案能把可写目录和网络约束作为系统保证，但不能把当前候选当成已完成。
首发前仍需处理系统 prerequisites、进程资源/停止/重启矩阵、完整证据和
实际构建/测试；默认断网时无法直接下载依赖，联网需要另一个明确产品方案。

## 选择的范围

本次只决定用户可见的命令权限边界。两种选择都不授权绕过审批、提前发布、
修改保留用户数据库或声明尚未通过的安全/恢复资格。文件闭环、MIT 许可、
首次真实模型配置及未配置时拒绝工作均保持已接受行为。
