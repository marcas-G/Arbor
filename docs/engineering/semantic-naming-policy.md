# Semantic-naming policy

Status: adopted for new code with architecture object 11 (first ratchet
slice, following the R5 source-line ratchet precedent). This document is the
narrow enforcement companion to Rule 1 of
[code-organization.md](code-organization.md), which states the naming
standard. Product semantics remain owned by the frozen design chain.

## Why a ratchet

The 2026-11-25 audit (see `code-organization.md`) found 381 test files and 24
production files named after planning phases, plus dozens of planning-coded
identifiers in production source. Renaming inventory wholesale would churn
frozen contracts and historical evidence, so — as with the R5 file-size
campaign — the repository freezes the existing inventory in a baseline and
makes any NEW planning-coded name a blocking CI failure. The inventory
shrinks monotonically in decomposition seams; growth of any baseline category
is a regression.

## What is checked

`node scripts/governance/check-semantic-naming.mjs --baseline <commit>`
reviews only work added after the baseline commit:

- **Added or renamed files**: repository-relative source paths whose path
  segments carry a planning code.
- **Added lines** (unified-diff hunks against the baseline tree) in changed
  source files: symbol declarations and `describe`/`it`/`test` name literals
  opening with a planning code. Comments are not declarations; comment text
  is stripped before matching.

Existing inventory is never re-reported. Lines that already existed at the
baseline commit are out of scope even when the surrounding file changes.

## Narrow rules (first batch)

1. **Path** — a source path matching
   `(^|[-_/])(p|ah)[0-9]{1,3}([-_/]|\.test\.|$)`.
2. **Symbol** — a declaration matching
   `(class|interface|type|const|function|enum)\s+(P[0-9]{1,3}|AH[0-9]{1,2})[A-Za-z]…`
   where the identifier continues as a real declaration (`=`, `{`, `(`, `|`
   union member, `extends` or line end). Import-list entries and bare
   references are not declarations.
3. **Test name** — a `describe`/`it`/`test` call whose string/template
   literal opens with `P<N>` or `AH<N>`.

Rules match only the historical shapes already present in the inventory; a
name like `WorkerLockClient`, `schemaV57` or `RecoveryBinding` never matches.

## Exemptions

- **Protocol and algorithm numerals**: `sha256`, `md5`, `crc32c`, `base64`,
  `xxHash64`, `schema-vNN`/`schemaVNN`, versioned contract names such as
  `ConversationCheckpointSourceManifestV1`. A planning code at the head of an
  identifier wins over a trailing version suffix
  (`P4SandboxUnavailableObservationV1` is inventory).
- **Frozen historical evidence**: `docs/**` and `planning/**` are out of
  scope entirely; they quote the codes as data.
- **Baseline paths**: every path in `scripts/governance/naming-baseline.json`
  is grandfathered for the path category. The symbol and test-name categories
  still apply to lines added after the baseline commit inside those files.

## Baseline and transition mode

`scripts/governance/naming-baseline.json` (schema
`arbor/semantic-naming-baseline/v1`) lists the inventory at the adoption
commit by category, each entry with its path and evidence. It is generated by
`scripts/governance/build-naming-baseline.mjs` and edited only by shrinking
it. Like the source-line gate, strict mode (no `--baseline`) fails on any
finding; transition mode with an explicit baseline reports legacy findings as
non-blocking context and blocks only new violations. The ratchet closes only
when the baseline is empty and the strict gate becomes the required check.

## CI

The workflow step runs after Manifest checks with the PR comparison base,
mirroring the source-size transition gate. Local invocations:

```text
pnpm check:naming
node --test scripts/governance/semantic-naming-lib.test.mjs
```
