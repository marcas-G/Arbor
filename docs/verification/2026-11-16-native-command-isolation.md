# Linux command isolation: real counterexample and implementation repair

Date: 2026-11-16. This records a candidate executor repair, not a Supported
qualification, ordinary browser journey or release acceptance.

## Counterexample

On Linux `6.12.115+deb13.1-amd64`, bubblewrap `0.12.0`, the previous actual
`buildBwrapPlan` allowed a sandboxed Python process to connect to a disposable
host Unix socket inside both ReadOnly and ReadWrite project mounts. The host
received `arbor-disposable-host-probe`. Host and sandbox network namespace IDs
were different. Read-only bind mounts and `--unshare-net` do not block pathname
Unix socket connections.

Original adapter-source SHA-256:
`c3202f572b2c8ef4363ae2325ebfa21fe2fd905e6e1beb3b55c210e75703d4f2`.
Local raw evidence:
`.test-results/native-preflight-2026-11-15T23-43-26.971Z/socket-result.json`.
The diagnostic bypassed capability admission to test the isolation primitive;
ordinary production was still gated and no Supported row was issued.

## Repair

The command launcher now uses util-linux `setpriv --no-new-privs
--seccomp-filter` with BPF generated by the system libseccomp. Bundled filters
are generated source; installed Arbor does not require Python or libseccomp
headers. Regenerate on Linux with:

```bash
python3 adapters/sandbox-native-posix/generate-command-filter.py
pnpm exec biome format --write adapters/sandbox-native-posix/src/index.ts
```

The trusted launcher writes the filter using a shell builtin before any project
command starts, then loads it before executing that command. Descendants retain
the filter. Without networking the launcher uses exec, avoiding an additional
resident shell and preserving the existing small process-count test envelope.

The filter denies new AF_UNIX sockets, namespace creation/entry and mount
operations, ptrace/process-memory operations, pidfd descriptor theft, and
io_uring paths that could bypass socket syscall filtering. clone3 returns
ENOSYS so libc can fall back to filtered clone for normal threads/processes.
Compatibility ABIs are denied. AF_UNIX socketpair remains available for local
parent/child IPC. Ordinary TCP remains available within the private namespace.

Bubblewrap additionally disables nested user namespaces, drops capabilities
and mounts proc read-only. The proc restriction prevents writes through
`/proc/<relay>/mem`; ptrace filtering alone would be insufficient. The trusted
network relay starts before command filtering and uses Node's
`--disable-sigusr1`, so a project command cannot signal it into opening an
unfiltered inspector. The relay still connects to the private broker socket.

This implementation currently also denies pathname Unix sockets created for
the command's own services. TCP services and socketpair IPC are the verified
alternatives; compatibility with arbitrary Unix-socket-dependent toolchains
has not been established. Filters exist for x64 and arm64, but this record has
real execution evidence for x64 only.

The executor also carries process-local tuple proofs from a decoded V2
qualification manifest. A request must match the manifest's exact profile,
network mode and evidence reference, and every requested limit must be less
than or equal to the manifest's validated limit. Tuple or limit mismatches are
rejected before the broker is created or a command is executed. This guard does
not issue authority rows.

## Verification

The new socket regressions live in the existing external functional network
harness, respecting the repository transport/package boundary. Commands:

```bash
ARBOR_RUN_NATIVE_POSIX=1 pnpm exec vitest run adapters/sandbox-native-posix/test/native-posix-policy.test.ts
ARBOR_RUN_NATIVE_POSIX=1 pnpm exec vitest run --config vitest.functional.config.ts tests/functional/process/network-proxy-broker.functional.test.ts -t 'native command boundary regression'
pnpm exec tsc -p tsconfig.test.json
pnpm exec vitest run --config vitest.architecture.config.ts
```

The executor file passed 46/46 after adding exact tuple/limit checks and the
external command-boundary cases passed 4/4; the V2 transport/lifecycle file
passed 18/18;
architecture passed 198/198 and test typecheck passed. The same tests preserve
output overflow, wall-time limits, process-tree stop and simultaneous isolated
invocation behavior. Test typecheck also exposed a missing expected lease
expiry in one P38 Stop fixture; the fixture now binds the actual read expires_at
alongside generation and worker identity.

An isolated compilation of the repaired adapter was also used to execute its
unmodified `buildBwrapPlan` through real bubblewrap. All seven diagnostics passed:

| Diagnostic | Observed result |
|---|---|
| ReadOnly project host socket | EPERM; host received no connection |
| ReadWrite project host socket | EPERM; host received no connection |
| Descendant process | Inherited socket denial |
| Internal TCP/thread/fork/exec | Completed successfully |
| unshare and nsenter escape | Operation not permitted |
| proc memory write | Read-only filesystem |
| Actual V2 broker, normal TLS, example.com | HTTP 200 |

## Remaining work

- No Supported row or first-install qualification bundle has been generated.
  Full artifact/limit binding (including the loaded command filter and setpriv),
  the complete qualification matrix and ordinary installation composition
  remain required.
- The extended V2 public Git/npm journey did not pass: the Git stage exited
  after approximately 30 seconds. Independently, host curl to github.com timed
  out after 12 seconds; an explicit request through the existing local Mihomo
  proxy ended with TLS EOF. The underlying routing/proxy cause is unresolved.
  Successful example.com HTTPS is not evidence that all development networking
  works. No proxy selection or system configuration was changed in this check.
- The V2 owning design files contain a supplement marked accepted, while the
  proposal manifest remains PREPARED_NOT_ACCEPTED. The acceptance/landing audit
  must be reconciled from actual records; this repair does not fabricate that
  record or modify design documents.
- Shared services across commands, browser previews, a complete packaged
  real-model coding journey and final human acceptance remain unproven.
