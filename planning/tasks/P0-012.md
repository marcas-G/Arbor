# P0-012 — Acceptance / Deliverable / Dependency revision binding

## Source

- DID §1.8 Dependency / Deliverable / Message
- DID §3.6 Acceptance / Deliverable / Dependency revision binding
- DID §12.8 C7 — Revision binding chain
- DID §12.11 C10 — Dependency truth table & immutable durable records
- DID §14.5 criterion 11

## Depends On

- P0-002 (typed IDs)
- P0-003 (revisions)
- P0-004 (domain errors)
- P0-011 (`Verification`, verdict)

## Blocked By

None (DG-01, DG-02 resolved in DID v1.4).

## Objective

Implement the revision-binding durable records `Acceptance`, `Deliverable`,
and `Dependency`, the `Dependency` lifecycle, the deterministic matcher,
and the pure cross-aggregate consequence functions, exactly as frozen.

## Inputs

- `AcceptanceId`, `DeliverableId`, `DependencyId`, `WorkId`,
  `WorkspaceId`, `VerificationId`, `ArtifactId`.
- `WorkRevision`, `DependencyRevision`, `DeliverableKind`, `ArtifactRole`.
- `Verification` + verdict (P0-011).

## Outputs

- `Acceptance` record: `workId`, `targetWorkRevision: WorkRevision`,
  `verificationId`, `actor`, `acceptedAt`. Immutable.
- `Deliverable` record: `deliverableId`, `sourceWorkId`,
  `sourceWorkRevision: WorkRevision`, `kind: DeliverableKind`,
  `artifacts: readonly { role: ArtifactRole, artifactId: ArtifactId }[]`.
  Immutable, version-stable.
- `ExpectedDeliverable` VO: `{ kind: DeliverableKind,
  requiredArtifactRoles: readonly ArtifactRole[] }` — contains no producer.
- `DeliverableKind` / `ArtifactRole` branded string value objects (owned
  here; not Entity IDs, no prefix).
- `ProducerBinding` ADT: `AnyProducer | WorkspaceBound(workspaceId) |
  WorkBound(workId)`.
- `Dependency` record: `dependencyId`, `consumerWorkId`,
  `producerBinding: ProducerBinding`, `revision: DependencyRevision`,
  `expectedDeliverable`, `state`, `satisfiedByDeliverableId?`,
  `satisfiedAtDependencyRevision?`.
- `DependencyLifecycle` ADT: `Unsatisfied | Satisfied | Withdrawn |
  Unfulfillable` (last three terminal).
- `DeliverableMatchView` and the frozen matcher
  `matchesExpectedDeliverable(producerBinding, expectedDeliverable, candidate): boolean`.
- Frozen consequence-function input facts:
  - `withdrawDependenciesOnWorkCancel(consumerWorkId, deps) -> deps'`
  - `markUnfulfillableOnProducerLoss(facts, deps) -> deps'` where `facts`
    records the triggering producer binding and loss kind:
    `{ binding: ProducerBinding, lost: WorkCancelled(workId) |
    WorkspaceRetired(workspaceId), replacedInSameGovernanceChange: boolean }`.
- Pure transitions: `DeclareDependency`, revise expected contract,
  `SatisfyDependency`, `WithdrawDependency`,
  `MarkDependencyUnfulfillable`.

## Must Hold

- `Acceptance` binds `workId` + `targetWorkRevision` + `verificationId`;
  it is immutable.
- `Deliverable.sourceWorkRevision` is fixed; a later Work refine does not
  retroactively satisfy a new revision's requirement.
- `Dependency` canonical consumer is `Work`, never a vague
  Workspace→Workspace relation.
- `SatisfyDependency` requires
  `targetDependencyRevision == current revision` **and**
  `matchesExpectedDeliverable` returning true.
- Matcher algorithm is exactly: (1) `producerBinding` matches candidate
  source (`AnyProducer` → true; `WorkspaceBound(ws)` →
  `candidate.sourceWorkspaceId == ws`; `WorkBound(w)` →
  `candidate.sourceWorkId == w`); (2) `candidate.kind == expected.kind`;
  (3) every `expected.requiredArtifactRoles` present in
  `candidate.artifactRoles`; all three → true.
- A satisfied record is immutable; contract changes create a new revision /
  Dependency, never a silent reinterpretation of old satisfaction.
- Cancel of the consumer Work deterministically withdraws its remaining
  `Unsatisfied` Dependencies via `withdrawDependenciesOnWorkCancel`.
- Producer loss rules follow `ProducerBinding`: `WorkBound(W)` + `W`
  Cancelled, or `WorkspaceBound(WS)` + `WS` Retired, or `WorkBound(W)`
  where `W` belongs to a retiring `WS` → `Unfulfillable` (unless already
  terminal or replacement committed atomically); `AnyProducer` alone does
  not imply `Unfulfillable`; cancellation of one Work under
  `WorkspaceBound(WS)` does not imply `Unfulfillable`.
- A new contract after a terminal dependency creates a new Dependency; it
  never rewrites history.
- No `OutputContract` Domain Entity is introduced.
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement cross-aggregate transaction orchestration or governance
  change-set application (P1).
- Do not implement `Message` / `Inbox` (not required for P0 completion).
- Do not add dependency states beyond the four.
- Do not implement the actual dependency scheduler / wait-for graph.
- Do not add metadata query DSL, regex predicates, semantic similarity,
  LLM matching, or arbitrary JSON predicates to the matcher.
- Do not add a `producer` field to `ExpectedDeliverable`.
- `ProduceDeliverable` is represented as an immutable record constructor,
  not a lifecycle transition (acceptable under §14.5 criterion 11).

## Acceptance

- Legal and illegal Dependency transitions match §12.11.
- Terminal Dependency mutation is rejected.
- Revision binding is enforced for satisfaction and acceptance.
- `Acceptance` / `Deliverable` are immutable record types (readonly fields).
- `withdrawDependenciesOnWorkCancel` and `markUnfulfillableOnProducerLoss`
  are pure and unit-tested with explicit input facts.
- No infrastructure import in the domain package.
