# P2-005 — `ExecutionRepository` (SQLite)

## Source

- P2 `02` §2, `04` §3.1, §4; DID v1.7 §7.3, §9.6

## Depends On

- P2-004

## Objective

Implement the invariant-shaped Execution repository over SQLite.

## Outputs

- `ExecutionRepositoryLive` with `tryAdmitMainExecution`, `admitExecution`, `findById`, `findActiveMainByWorkspace`, `requestStop`, `settle`, `currentLease`, `tryAcquireLease`, `renewLease`, `releaseLease`, `findExpiredActiveExecutions`, `findUnsettledExecutions`.

## Must Hold

- Main admission pre-checks inside `BEGIN IMMEDIATE`; partial unique index is the safety net.
- `settle` is settle-once CAS (`WHERE settled_at IS NULL RETURNING`).
- Lease CAS per `04` §4 (acquire only when absent/expired; renew/release on `(worker_id, generation)`).
- All methods require `TransactionScope`; adapter errors translated to `ExecutionRepositoryError`.

## Must Not Decide

- No lease lifecycle policy (that is `LeaseService`, P2-006).
- No command pipeline logic.

## Acceptance

- Second active main returns `None`; `ExecutionBound` always admitted.
- `settle` returns no row on a second call.
- Expired lease can be re-acquired; a live lease cannot.

pnpm test p2-execution-repository
