- DID §1.2 Project & Workspace Tree

- DID §3.2 Workspace
- DID §12.11 C10 — Workspace truth table

## Depends On

- P0-005 (Project)
- P0-007 (`ResponsibilityDefinition` / `ResourceBoundary` / ownership types)
- P0-009 (`WorkspaceExecution.focus` used by `SelectCurrentWork`)
- P0-010 (`SessionBinding` / `WorkspacePrimary`)
- P0-012 (`ProducerBinding` used by `RetireWorkspace`)
- P0-015 (`AgentBinding` / `AgentProfile`)

## Owns

- `WorkspacePolicy` value object (opaque placeholder in P0; no policy

## Blocked By

None (DG-01, DG-03, DG-05 resolved in System Design v1.3 / DID v1.4).

## Objective

Implement the pure `Workspace` aggregate state model and its legal
structural mutations, and make the forbidden transitions unconstructable.

## Inputs

- `WorkspaceId`, `ProjectId`, `WorkId`, `SessionId`, `Revision`,
  `ResponsibilityRevision`, `ResourceBoundaryRevision`.
- `ResponsibilityDefinition`, `ResourceBoundary`, `ResourceOwnershipClaim`.
- `SessionBinding`, `ResponsibilityBoundAgentBinding`, `WorkspacePolicy`
  (owned here).
- `ProducerBinding` + incoming-Dependency facts (for the retire
  precondition).
- `WorkspaceExecution.focus` fact (for `SelectCurrentWork`).

## Outputs

- `Workspace` data type with fields: `workspaceId`, `projectId`,
  `parentWorkspaceId?`, `name`, `responsibilityDefinition`,
  `responsibilityRevision`, `resourceBoundary`,
  `resourceBoundaryRevision`, `agentBinding: ResponsibilityBoundAgentBinding`,
  `primarySessionId`, `currentWorkId?`, `workspacePolicy`,
  `workspacePolicyRevision`, `revision`, `lifecycle: Active | Retired`.
- Pure transitions:
  - `CreateChildWorkspace` (parent same Project + authority)
  - `ChangeResponsibility` (authority + expected revision)
  - `UpdateResourceBoundary` (authority + expected revision + ownership
    overlap check)
  - `UpdateWorkspacePolicy` (authority + expected revision)
  - `SelectCurrentWork` (target Work belongs to Workspace + `Open`; no
    conflicting Active Main Execution)
  - `ReplacePrimarySession` (target is `WorkspacePrimary`; no Active Main
    Execution)
  - `RetireWorkspace` (all §1.4A preconditions)
- `WorkspaceLineage` durable record type (not an aggregate root).
- `WorkspacePolicy` value object (owned here).

## Must Hold

- `parentWorkspaceId` is immutable after creation.
- No `ReparentWorkspace`, `MoveWorkspace`, or
  `ReactivateRetiredWorkspace` — these must not exist as operations.
- At most one `currentWorkId`; it must belong to this Workspace.
- `ChangeResponsibility` increments `responsibilityRevision`.
- `UpdateResourceBoundary` increments `resourceBoundaryRevision` and
  returns the updated ownership claims in the same resulting state
  (transaction atomicity is P1); committed state satisfies
  `ResourceOwnershipClaim ⊆ ResourceBoundary` and
  `ResourceBoundary.basisResponsibilityRevision == responsibilityRevision`.
- `UpdateWorkspacePolicy` increments both `revision` and
  `workspacePolicyRevision`; other structural mutations increment only
  `revision`.
- `primarySessionId` must be a `WorkspacePrimary` binding.
- `Workspace.agentBinding` is `ResponsibilityBoundAgentBinding`;
  `ExecutionBoundAgentBinding` is Execution-scoped only.
- `ReplacePrimarySession` requires no Active Main Execution and does not
  change any already-admitted Execution's `sessionId`.
- `SelectCurrentWork` is forbidden only when there is an Active Main
  Execution whose focus is the old current Work; a `Coordination`-focused
  Active Main Execution may commit it after validating the candidate.
- `RetireWorkspace` requires: non-Root, `Active`, no Active Main Execution,
  `currentWorkId == None`, no Open Work, no Active Child Workspace, no
  active ResourceOwnershipClaim, and no unresolved incoming Dependency
  whose `producerBinding` is `WorkspaceBound(thisWorkspace)` or
  `WorkBound(a Work owned by thisWorkspace)` (unless resolved/replaced in
  the same governance change). `Retired` is terminal.
- `Retired` Workspace rejects AssignWork, AdmitExecution,
  CreateChildWorkspace, and Responsibility mutation.
- Workspace Tree never crosses Projects.
- Children/subtree are queries, not stored `childrenIds[]`.
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement workspace reparenting or relocation; organizational
  change is replacement, not relocation (§1.4A).
- Do not move `Work` between Workspaces; successor Work is created and
  linked by provenance.
- Do not implement Active Main Execution uniqueness enforcement (that is
  L3 persistence/runtime, P1+); only express the pure precondition.
- Do not implement resource resolution I/O or environment revision checks.
- No persistence, no repository, no transaction orchestration.

## Acceptance

- All seven legal operations match §12.11 exactly.
- Exported-symbol allowlist test: no `ReparentWorkspace`,
  `MoveWorkspace`, or `ReactivateRetiredWorkspace` symbol exists.
- `CurrentWork ≤ 1` and "current Work belongs to Workspace" hold.
- Retire preconditions are all enforced as typed rejections (including the
  `ProducerBinding` rule).
- No infrastructure import in the domain package.
