# P0-005 — Project aggregate & transitions

## Source

- DID §3.1 Project
- DID §1.2 Project & Workspace Tree
- DID §12.11 C10 — Project truth table
- DID §14.5 criterion 3

## Depends On

- P0-002 (typed IDs)
- P0-003 (revisions)
- P0-004 (domain errors)

## Owns

- `ProjectPolicy` value object (the Project-side capability/policy ceiling
  vocabulary). P0 treats it as an **opaque placeholder** — no policy
  evaluation or schema is implemented here (capability ceiling is L2, P1+).
  `WorkspacePolicy` is owned by P0-006; P0-015 must not redefine either.

## Blocked By

None (DG-03 resolved in DID v1.4).

## Objective

Implement the pure `Project` aggregate state model and its transition
functions exactly as frozen in the §12.11 Project truth table.

## Inputs

- `ProjectId`, `WorkspaceId`, `Revision`.
- `ProjectPolicy` value object (policy/capability ceiling vocabulary).
- `DomainError` union.

## Outputs

- `Project` data type with fields: `projectId`, `name`, `rootWorkspaceId`,
  `projectPolicy`, `projectPolicyRevision`, default configuration,
  `environmentRef`, `lifecycle: Open | Closed`, `revision`.
- Pure constructors / transitions:
  - create (from valid root/bootstrap input) → `Open`
  - `UpdateProjectPolicy` → `Open`, `revision++` and
    `projectPolicyRevision++`
  - `CloseProject` → `Closed`
- Pure predicates for lifecycle.

## Must Hold

- Exactly one Root Workspace per Project (`rootWorkspaceId` is singular).
- `Closed` lifecycle is terminal: any further lifecycle mutation is
  **illegal** and returns a typed error, never a new state.
- `UpdateProjectPolicy` requires authority + expected revision, and
  increments both `revision` and `projectPolicyRevision`; other mutations
  increment only `revision`.
- `CloseProject` requires authority.
- Project Policy is a capability/policy **ceiling** for descendants.
- `Closed` still permits read/recovery/audit semantics; it forbids
  admission of new autonomous Execution (this predicate is expressed
  purely here; enforcement is later layers).
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement the atomic multi-aggregate creation of
  Project + Root Workspace + Primary Session (that is an application
  transaction boundary, P1).
- Do not implement `ReparentWorkspace` or any tree mutation.
- Do not implement authority evaluation beyond accepting a pure
  authority/precondition input.
- No persistence, no revision allocation service.

## Acceptance

- Legal transitions match §12.11 exactly.
- `Closed → any lifecycle mutation` is rejected with a typed error.
- `UpdateProjectPolicy` increments `revision` and `projectPolicyRevision`;
  `CloseProject` increments only `revision`.
- `Project` has exactly one `rootWorkspaceId`; constructing a Project with
  zero or multiple roots is a type error (field presence test).
- No infrastructure import in the domain package.
