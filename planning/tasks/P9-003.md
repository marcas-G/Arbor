# P9-003 — B-2 completion-fact settle + recovery drive triggers T1–T4 (GQ3) + D1/D2/D6

## Source

- P9 `01` §2 (B-2 deterministic settle), §3 (GQ3 trigger surface), `03` §2 (T1–T4 timing, single-flight, hook set), `02` §4 (D1/D2/D6); P2 `06` §2/§4/§6 (nine steps, settle rules, no authority resurrection); SD §10.6

## Depends On

- P9-002

## Objective

Implement the second deterministic settle case (durable completion fact →
corresponding Completed form) and wire the missing production recovery
drives: startup full pass (T1), periodic/event-triggered sweeps (T2/T3), and
the targeted pre-dispatch check (T4) — the GQ3 frozen trigger surface.

## Outputs

- Completion-fact settle in the RecoveryController path + daemon startup/sweep/pre-dispatch drives + `p9-recovery-drive` suite.

## Must Hold

- **B-2**: a durable completion fact (`Completed(CompletionClaimed | Yielded …)` persisted in the settlement trace) found on an unsettled execution settles to the **corresponding Completed form** — never a guess, never a downgrade (`01` §2).
- B-2 follows the same RecoveryController authority path: gateway submission, recovery origin, deterministic commandId `f("recovery", executionId, "completion")`; idempotent replay returns the existing receipt.
- **T1**: startup full recovery runs the nine-step pass (P2 `06` §2) **exactly once per daemon startup**, in frozen order, **before any new dispatch or admission**; crash during T1 → restart re-runs T1 with idempotent re-entry (D2: no double settlement, no duplicate wake, lease invalidation monotone, no duplicate entities).
- **T2/T3**: periodic + event-triggered sweeps run the same nine-step pass; single-flight per daemon (P2 `05` §8 discipline); a sweep concurrent with T4 is harmless (T4 is a read). T3 hook set **frozen**: (a) ExecutionSettled observed; (b) expired lease observed (any lease CAS / fence check / pre-dispatch check seeing `expires_at <= now`); (c) consumer dead-letter written — adding a hook is a contract change, not an implementation choice.
- **T4 prohibition (GQ3)**: the targeted pre-dispatch check is the **lease-fence predicate ONLY** — never the nine-step recovery; conflating them is a contract violation. "Targeted" is reserved for T4 only.
- Recovery pass triggers produce **no organizational mutations** (SD §10.6: Runtime failure != organizational change).
- D6: leased Active execution in the dirty-restart fixture → settle-or-Active per deterministic rules only; recovery never resurrects the old worker's authority (P2 `06` §6).
- Sweeps drive reevaluation via the existing `reevaluate` loop (P2 `05` §4); no new scheduling decision (DF2 bottom line, `02` §9).
- Sweep interval numerics empirical (task-level).

## Must Not Decide

- No nine-step order change; no settle-rule changes beyond the P2-frozen two deterministic cases; no T3 hook additions; no per-dispatch full recovery under any flag; no interval numerics as contract; no RuntimeSafetyGate persistence (`03` §4).

## Acceptance

- Completion-fact settle + replay idempotency mechanically checked; T1 exactly-once-before-dispatch asserted (no dispatch/admission observed before the pass completes); D2 crash-during-recovery convergence green; each T3 hook (a–c) fires a coalesced sweep; T4 path performs a single-predicate read (nine-step observables absent).
