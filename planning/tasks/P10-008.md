# P10-008 — Inbox view + state-reconciliation audit face

## Source

- P10 `04` §2 (Inbox M1 fix: state reconciliation face), §1 item 2 (projection-side view lifetime); P10 `01` §1 (Inbox view row); P10 `05` §1 (InboxViewReq core); P9 `05` §3.2 (Inbox as P10 surface); SD §7.4; P6 inbox semantics (FROZEN)

## Depends On

- P10-003

## Objective

The Inbox view/query over `inbox_entries` (P6-owned semantics; P10 owns
view/query/rebuild face) plus the state-reconciliation audit pass — the
P10-owned face comparing `inbox_entries` against canonical
message/specialist-settlement facts, producing a drift report and
operator-triggered repair.

## Outputs

- InboxView derive + query; reconciliation audit pass + drift report; operator-triggered repair path; `p10-inbox-view` suite.

## Must Hold

- The P6 store is **command-path maintained (not event-replayed)** — its "rebuild" face is **state reconciliation**: compare `inbox_entries` against canonical message/specialist-settlement facts; repair goes **via the P6 admission paths, never direct writes**.
- Reconciliation is audit + operator-triggered repair only — no automatic repair; no P6 inbox semantics change.
- Projection-side retention: consumed entries' **view lifetime** is bounded (summary aging) — projection rows only; **underlying rows stay canonical (P6 semantics unchanged)**.
- `InboxViewReq {workspaceId}` → `{unconsumed[{entryKey, kind, summary, watermark}]}` per the frozen core; watermark carried per the port envelope.
- No view writes anything outside the declared projection-side view-lifecycle rows.

## Must Not Decide

- No retention of canonical inbox rows; no P6 channel/promotion/consumption semantics change; no transport.

## Acceptance

- Seeded drift fixtures (missing / extra / duplicated marker shapes) → reconciliation report exact; repair via P6 admission paths converges the report to zero-drift; canonical rows untouched by the audit pass (snapshot).
