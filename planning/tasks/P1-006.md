## Objective

Implement command resolution persistence and the domain event journal.

## Outputs

- `CommandStore`: `findResolution`, `insertCommitted`,
  `insertTerminalRejected`, `recordResolvingAttempt`, `recordRetryableAttempt`.
- `DomainEventJournal`: `append` (project-local sequence upsert),
  `readAfter`, `lastSequence` (0 when absent).
- Fingerprint column handling: `semantic_request_fingerprint`,
  `schema_version`, `fingerprint_algorithm_version`.

## Must Hold

- `commands` persists only `Committed | TerminalRejected`; never `Pending`.
- Single transaction writes canonical receipt; no dual transaction.
- Sequence allocation uses `INSERT ... ON CONFLICT DO UPDATE ... RETURNING`;
  independent of `domain_events` rows.
- `command_attempts` has no FK to `commands`; resolving attempt in the command
  tx, retryable attempt in a separate scope.
- `commands` never hard-deleted.

## Must Not Decide

- No command handlers.
- No consumer/projection logic (P1-008).
- No `Pending` state.

## Acceptance

- Committed / TerminalRejected rows round-trip with fingerprint columns.
- First event of a new project allocates sequence 1 (no pre-seed).
- Concurrent append serializes without duplicate sequences.
- `lastSequence` absent = 0.
