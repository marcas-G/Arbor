# P1-014 — Recovery matrix tests

## Source

- `docs/design/implementation/P1/06-recovery-matrix.md`
- DID v1.6 §7.4, §12.5, §12.6

## Depends On

- P1-008 (journal consumer)
- P1-010, P1-011, P1-012 (P1 command handlers)

## Objective

Prove the frozen crash-point matrix (C1–C11, P1–P4, ownership, migration).

## Outputs

- Tests exercising: pre-commit crash/rollback (no partial state), commit
  durability, post-commit replay, concurrent duplicate, `SQLITE_BUSY` →
  operational failure, poison-event skip, offset re-delivery, ownership
  rollback + `ResourceResolutionStale`, migration failure.

## Must Hold

- Each crash point has a deterministic, all-or-nothing outcome.
- Operational failure produces no authoritative resolution and records a
  retryable attempt in a separate scope.
- Consumers are idempotent; poison does not stall.

## Must Not Decide

- No worker/lease crash tests (P2).
- No provider/tool reconciliation (P3/P4).

## Acceptance

- Every matrix row has a passing test (or an explicit P2+ exclusion note).
- No test relies on nondeterministic timing.

## Verification

```bash
pnpm test p1-recovery
pnpm check
```
