# P2-006 — `LeaseService` + fence/stop predicates

## Source

- P2 `03` §2–§4, `04` §4, `02` §6; DID v1.7 §6.3, §9.7

## Depends On

- P2-005

## Objective

Implement lease acquisition/renewal/release/invalidation and the authoritative fence/stop predicates.

## Outputs

- `LeaseServiceLive` (`acquire`, `renew`, `release`, `invalidateExpired`).
- Fence predicate + stop predicate queries (`03` §3–§4).

## Must Hold

- `generation` monotonic (`COALESCE(MAX(generation)+1, 0)`).
- Fence validity requires matching `execution_id + generation` and `settled_at IS NULL`.
- Expired-lease invalidation never settles an Execution.
- `LeaseLost` (local) vs authoritative rejection are distinguished.

## Must Not Decide

- No worker crash settlement.
- No transaction-external fence pre-check as authority.

## Acceptance

- Acquire → generation 0; release+re-acquire → generation 1.
- Stale generation renewal fails.
- Expired lease invalidated; `findExpiredActiveExecutions` empty afterwards.
