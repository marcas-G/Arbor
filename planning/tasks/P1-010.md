# P1-010 — `CreateProject` handler

## Source

- `docs/design/implementation/P1/01-command-contracts.md` §5
- `docs/design/implementation/P1/04-sqlite-schema.md` §3.1
- DID v1.6 §12.11 (CreateProject bootstrap)

## Depends On

- P1-005 (repositories)
- P1-006 (CommandStore / DomainEventJournal)
- P1-009 (CommandGateway)

## Blocked By

- P1-DG-11 (authority predicate) — OPEN; the authority rule must be frozen
  before this handler's authority precondition is implementable.

## Objective

Implement the `CreateProject` command handler: single-transaction creation of
Project + Root Workspace + WorkspacePrimary Session.

## Outputs

- `CreateProjectPayload` and handler.
- Result `{ projectId, rootWorkspaceId, primarySessionId }`.
- Events `ProjectCreated → WorkspaceCreated` (ordered, same transaction).

## Must Hold

- Single transaction; deferred FKs validate at COMMIT.
- `envelope.projectId` is the new Project id (caller-preallocated); ids in the
  payload are caller-preallocated.
- No Session Domain Event (DID §5.3).
- `resourceBoundary.basisResponsibilityRevision == responsibilityRevision`
  else `AuthorityDenied`.
- Rejections: `AuthorityDenied`; idempotency handled by the gateway.

## Must Not Decide

- No non-P1 commands.
- No workspace formation/handoff behavior (P6).

## Acceptance

- Creates Project + Root Workspace + Session atomically.
- Emits exactly `ProjectCreated` then `WorkspaceCreated`.
- Missing authority / bad basis revision rejected.
- Replay of the same command returns the existing receipt.
