# P0-011 — Verification aggregate & verdict ADT

## Source

- DID §3.5 Verification
- DID §3.6 revision binding
- DID §12.11 C10 — Verification truth table
- DID §14.5 criterion 8

## Depends On

- P0-002 (typed IDs)
- P0-003 (revisions)
- P0-004 (domain errors)

## Objective

Implement the pure `Verification` aggregate, its `VerificationMission`
value object, and the fixed `PASS | FAIL | UNKNOWN` verdict ADT.

## Inputs

- `VerificationId`, `WorkId`, `DeliverableId`, `ArtifactId`,
  `ExecutionId`, `EvidenceId`, `WorkRevision`.

## Outputs

- `VerificationMission` VO: goal, criteria, risk requirements.
- `VerificationVerdict` ADT: `Pass | Fail | Unknown` (exactly three).
- `Verification` data type with: `verificationId`, `workId`,
  `targetWorkRevision: WorkRevision`, `missionSnapshot`,
  `targetDeliverables`, `targetArtifactVersions`,
  `targetEnvironmentRevision?`, `environmentSnapshotRef?`, `evidenceRefs`,
  `verificationExecutionIds`, `verdict?`.
- Pure transitions:
  - `StartVerification` → `Open`
  - `RecordVerificationEvidence` → `Open`
  - `ConcludeVerification(Pass | Fail | Unknown)` → `Concluded(verdict)`

## Must Hold

- Verdict is fixed to `PASS / FAIL / UNKNOWN`.
- A concluded verdict is immutable; mutating it is **illegal**.
- Re-verification creates a **new** `Verification` identity.
- Verification is bound to a concrete Work / Deliverable / Artifact
  revision (`targetWorkRevision`).
- Producer / Verifier / Acceptance are three separate roles.
- The verifier defaults to read-only access to producer formal output.
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement the verification runtime, verifier agent, or evidence
  collection (P8).
- Do not implement acceptance (P0-012) or `CompleteWork` (P0-008).
- Do not add verdict values beyond `PASS / FAIL / UNKNOWN`.
- Do not implement environment snapshot resolution.

## Acceptance

- `VerificationVerdict` has exactly three variants (switch with `never`
  default).
- `Concluded` carries a readonly verdict; a mutation attempt fails to
  compile / throws (type + runtime immutability test).
- Re-verification produces a distinct identity.
- Version binding is enforced as a pure precondition.
- No infrastructure import in the domain package.
