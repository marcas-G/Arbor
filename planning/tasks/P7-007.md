# P7-007 — Deliver primitive (SendMessage kind, ChildDelivered wake, directive)

## Source

- P7 `02` §2–§8; DID v1.10 §8.15/§8.18, G2

## Depends On

- P7-002, P7-004

## Objective

Wire the Deliver communication primitive: `SendMessage` kind=Deliver preconditions, Inbox admission, `ChildDelivered` wake at the same commit boundary, and the `Deliver` directive.

## Outputs

- SendMessage Deliver branch + `DeliverDirectiveSpec` handler.

## Must Hold

- `deliverableId` references, never creates; `bodyRef` is a bounded summary, artifact content never inlined.
- Direction frozen child → direct parent: sender must be the Workspace owning `deliverable.sourceWorkId`, recipient must be its direct parent — resolved canonically, never model-asserted; violations → `AuthorityDenied`.
- Inbox admission stays upsert-by-key in `InboxEntry.kind = "Message"` — no enum expansion; summary references the deliverable; redelivery is a no-op.
- Same transaction: MessageStore append + `MessageSent` + Inbox admission + `wake(parent, ChildDelivered)`.
- Promotion set for Deliver is **empty** — Deliver never satisfies a Dependency; `promoteInboxArrival` grows a zero-effect Deliver branch.
- Directive recipient is derived, never model-chosen; rejections are model-visible observations.

## Must Not Decide

- No Message/Inbox semantics beyond the G2-authorized kind expansion; no satisfaction coupling to the Deliver channel; no wake mechanism changes (P2).

## Acceptance

- Deliver lands in parent Inbox + `ChildDelivered` wake + zero Dependency effects; Report channel keeps zero canonical side effects (D2 regression).
