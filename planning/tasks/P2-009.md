# P2-009 — `AdmitExecution` handler

## Source

- P2 `01` §4–§5; DID v1.7 §3.4, §9.6, §12.3, G5

## Depends On

- P2-005
- P2-006
- P2-008

## Objective

Implement the `AdmitExecution` command handler for `WorkspaceMain` and `ExecutionBound`.

## Outputs

- `AdmitExecutionPayload` / `AdmitExecutionResult`.
- `makeAdmitExecutionHandler` with `AdmitExecutionAuthority` and `StopAdmission.Unclassified`.

## Must Hold

- `WorkspaceMain`: snapshot `workspace.primarySessionId`; one-active-main enforced (`ActiveExecutionConflict`).
- `ExecutionBound`: atomic Execution + `ExecutionScoped` Session in one transaction.
- All IDs caller-preallocated; handlers never generate IDs.
- Emits `ExecutionAdmitted`; no Session Domain Event.
- Authority exact-match per `01` §4 (runtime origin `System` only).

## Must Not Decide

- No specialist spawn/delegation semantics.
- No lease acquisition in admission.
- No `External` origin admission.

## Acceptance

- Project + Workspace + Session created; `ExecutionAdmitted` emitted; session fixed.
- Second active main rejected; `ExecutionBound` admitted concurrently.
- Missing workspace → `WorkspaceNotFound`; retired workspace → `TerminalLifecycleMutation`.

pnpm test p2-admit-execution
