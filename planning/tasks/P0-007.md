# P0-007 — Responsibility / resource ownership algebra

## Source

- DID §1.5 ResponsibilityDefinition, ResourceBoundary & Resource Ownership
- DID §12.9 C8 — Resource ownership algebra
- DID §12.10 C9 — resource boundary / ownership row
- DID §14.5 criterion 7

## Depends On

- P0-002 (typed IDs)
- P0-003 (revisions)
- P0-004 (domain errors)

## Objective

Implement the value objects and pure algebra that connect a Workspace's
semantic responsibility to concrete, non-overlapping write ownership.

## Inputs

- `ResourceBoundaryRevision`, `ResponsibilityRevision`.
- `ResourceAddress` ADT: `FileTree`, `GitWorktree`, `DatabaseNamespace`,
  `ExternalResource`.
- `CanonicalResourceRegion { resourceSpaceId, normalizedRegion }`.

## Outputs

- `ResponsibilityDefinition` VO: `purpose`, `ownedResponsibilities`,
  `obligations`, `includes`, `excludes`, `interfaces`, **with codec**.
- `ResourceBoundary` VO (with `basisResponsibilityRevision`) **with codec**.
- `ResourceAddress` ADT with codecs for the four families.
- `CanonicalResourceRegion` VO `{ resourceSpaceId, normalizedRegion }`
  **with codec**. `normalizedRegion` is **opaque in P0**: its concrete
  encoding is not decided here (P1, DID §13).
- `RegionComparator<R>` **protocol** (observable contract frozen; the exact
  TypeScript encoding is implementation-free), e.g.:
  ```ts
  type RegionComparator<R> = {
    contains(a: R, b: R): boolean
    overlaps(a: R, b: R): boolean
  }
  ```
- Pure ownership-conflict function:
  `sameSpaceConflict(a, b, comparator) = (a.resourceSpaceId === b.resourceSpaceId)
  && comparator.overlaps(a.normalizedRegion, b.normalizedRegion)`.
- `ResourceOwnershipClaim` durable record type.
- Pure algebra connecting the chain
  `ResponsibilityDefinition → ResourceBoundary → ResourceAddress →
  CanonicalResourceRegion → ResourceOwnershipClaim`.

## Must Hold

- Codecs round-trip for all four VOs required by §14.5 criterion 7:
  `ResponsibilityDefinition`, `ResourceBoundary`, `ResourceAddress`,
  `CanonicalResourceRegion`.
- Ownership overlap is decided on **canonical backing resources**, never on
  raw address strings.
- Spatial comparison requires the **same `resourceSpaceId`**. Different
  `resourceSpaceId` → `overlaps = false` and `contains = false` (never
  throws, never true).
- Frozen algebra laws for a comparator within one space:
  - `overlaps(a, b) == overlaps(b, a)`
  - `contains(a, a) == true`
  - `contains(a, b) && contains(b, c)` → `contains(a, c)`
  - `contains(a, b)` → `overlaps(a, b)`
  - `!overlaps(a, b)` → no exclusive-write conflict between `a` and `b`
- Exclusive-write conflict is exactly `sameSpaceConflict`; the algebra never
  invents a second conflict rule.
- `contains` / `overlaps` are pure, deterministic, and total.
- `ResourceBoundary`, `ResourceOwnershipClaim`, and `Permission` remain
  three distinct concepts and are never merged.
- Read visibility may overlap; formal write ownership does not.
- `ResourceAddress` is **not** a uniqueness key (aliases exist). The alias
  resolution itself is P1; in P0 the algebra operates on already-resolved
  `CanonicalResourceRegion` values.

## Must Not Decide

- Do not implement `ProjectEnvironmentPort` resolution, filesystem I/O, or
  environment revision staleness handling (`ResourceResolutionStale`) —
  that is a P1+ adapter concern.
- Do not implement a concrete (or fake) filesystem / worktree / namespace
  comparator. P0 defines only the `RegionComparator` protocol and the pure
  ownership logic; P1 supplies the concrete `normalizedRegion` and
  comparator.
- Do not decide the `normalizedRegion` internal encoding (path trie,
  segment array, namespace tuple, …) — P1 blocker (§13).
- Do not implement the transaction sequence for ownership commits.
- Do not choose physical encoding, indexes, or DDL.
- Do not let `Permission` widen a boundary or override ownership.

## Acceptance

- All four `ResourceAddress` variants round-trip through codecs.
- `ResponsibilityDefinition`, `ResourceBoundary`, and
  `CanonicalResourceRegion` codecs round-trip.
- `contains` / `overlaps` are proven deterministic and total by tests,
  including cross-space non-overlap and same-space containment/overlap.
- The frozen algebra laws are asserted against an in-memory test
  comparator (the test comparator is throwaway; no production comparator
  is implemented).
- Different `resourceSpaceId` yields `overlaps = false` and
  `contains = false`.
- `ResourceOwnershipClaim ⊆ ResourceBoundary` is expressible as a pure
  predicate.
- No infrastructure import in the domain package.
