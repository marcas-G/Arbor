# P0-010 — Session runtime aggregate

## Source

- DID §1.7 Session
- DID §12.7 C6 — Fixed Execution ↔ Session binding
- DID §12.11 C10 — Session
- DID §3.4 admission-time fixed binding

## Depends On

- P0-002 (typed IDs)
- P0-003 (scoped ordinals)
- P0-004 (domain errors)

## Objective

Implement the pure `Session` runtime aggregate model: durable cognitive
continuity that carries **no** canonical business truth.

## Inputs

- `SessionId`, `WorkspaceId`, `ExecutionId`, `ContextEpochNumber`.

## Outputs

- `SessionBinding` ADT:
  - `WorkspacePrimary(workspaceId)`
  - `ExecutionScoped(executionId)`
- `Session` data type with: cognitive history references, `ContextEpoch`,
  checkpoint, provider continuation metadata, model/output continuation
  state.
- `SessionEntry` append-only local sequence type.
- Pure operations: append entry (given valid execution/fence input),
  create checkpoint / new epoch.

## Must Hold

- Session identity is durable; `SessionEntry` is append-only by local
  sequence; `ContextEpoch` is a monotonic local ordinal.
- Session **never** stores: Responsibility canonical truth, Current Work
  canonical truth, Permission, Dependency status, Verification verdict, or
  Resource ownership.
- Compaction creates a new checkpoint/epoch and does not change canonical
  business truth.
- Workspace primary replacement changes the Workspace pointer and does not
  rewrite the old Session.
- An already-admitted Execution continues to bind its admission-time
  Session; `execution.sessionId` is immutable.
- Session has no business lifecycle state machine.
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement worker fencing validation, persistence of entries, or
  provider continuation I/O (Runtime/persistence, P1+).
- Do not introduce Session lifecycle states such as Active/Closed.
- Do not let Session become an authority source.

## Acceptance

- Both `SessionBinding` variants exist and are exhaustive.
- Append/epoch operations are pure and monotonic.
- Schema field-presence test: `Session` has no field named/typed as
  Responsibility, Current Work, Permission, Dependency status,
  Verification verdict, or Resource ownership.
- No infrastructure import in the domain package.
