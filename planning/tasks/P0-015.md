# P0-015 — Pure authority / policy vocabulary

## Source

- DID §1.6 Agent is not a long-lived Domain Entity
- DID §1.1 `PermissionGrant`, `Decision`, `AgentBinding`, `AgentProfile`
- DID §12.11 C10 — PermissionGrant truth table
- DID §12.10 C9 — Permission row
- DID §6.2 enforcement matrix (Parent/Sibling authority, Tool authority chain rows)
- DID §14.5 criterion 13

## Depends On

- P0-002 (typed IDs)
- P0-003 (scoped ordinals)
- P0-004 (domain errors)

## Owns

- `AgentBinding` ADT, `AgentProfile`, `PermissionGrant`, `Decision`.
- Does **not** own `ProjectPolicy` (P0-005) or `WorkspacePolicy` (P0-006).

## Blocked By

None (DG-05 resolved in System Design v1.3 / DID v1.4).

## Objective

Implement the pure authority / agent-binding vocabulary used by Workspace
and Execution, and the `PermissionGrant` lifecycle. There is no long-lived
Agent entity.

## Inputs

- `PermissionGrantId`, `WorkspaceId`, `ExecutionId`, `DecisionId`,
  `ArtifactId`.

## Outputs

- `AgentBinding` umbrella vocabulary:
  - `ResponsibilityBoundAgentBinding` (→ Workspace, long-lived
    session/memory)
  - `ExecutionBoundAgentBinding` (→ Execution, temporary mission)
- `AgentProfile` reusable configuration (default HOW).
- `PermissionGrant` record: scope, issuer, lifetime; lifecycle
  `Active | Revoked`.
- `Decision` durable record with supersede semantics.
- Pure transitions: `GrantPermission` (absent → `Active`),
  `RevokePermission` (`Active` → `Revoked`).

## Must Hold

- There is **no** `AgentId` and no long-lived `Agent` aggregate; Agent is a
  runtime execution role only.
- Long-lived agent continuity derives from `WorkspaceId` +
  `ResponsibilityDefinition` + `ResponsibilityBoundAgentBinding` +
  Primary Session + Workspace Memory.
- `AgentProfile` defines default HOW and is never a source of
  responsibility or permission.
- `PermissionGrant` has explicit scope, issuer, and lifetime.
- `Revoked` is terminal; reactivating the same grant is **illegal**.
- Time expiry is an effective-authorization evaluation, not deletion of
  history; re-granting creates a new grant identity.
- A permission cannot widen a `ResourceBoundary` nor override the write
  ownership invariant (stated as a vocabulary constraint; the ceiling
  evaluation itself is L2, not implemented here).
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement authority/ceiling evaluation; it is L2 (application) and
  needs cross-aggregate reads (§6.2). P0 provides vocabulary only.
- Do not define `ProjectPolicy` / `WorkspacePolicy` (owned by P0-005 /
  P0-006).
- Do not implement Permission as a merge of `ResourceBoundary` /
  `ResourceOwnershipClaim`.
- Do not implement Decision workflow / approval process.
- Do not add `AgentId` or an Agent aggregate.

## Acceptance

- `AgentBinding` has exactly the two frozen variants
  (`ResponsibilityBoundAgentBinding` / `ExecutionBoundAgentBinding`), with
  `Workspace.agentBinding` typed `ResponsibilityBoundAgentBinding` (switch
  with `never` default).
- `PermissionGrant` transition table matches §12.11.
- `Revoked` reactivation is rejected.
- Exported-symbol test: no `AgentId` / Agent aggregate exists.
- No infrastructure import in the domain package.
