# P0-004 — Domain error algebra

## Source

- DID §6A.1 Error / Outcome / Control Flow / Unknown separation
- DID §6A.2 No universal `ArborError`
- DID §6A.3 FailureDisposition
- DID §0A.6 Error channel for architecture audit
- DID §14.4 rules 4–7

## Depends On

- P0-001

## Objective

Define the typed domain failure vocabulary and its disposition semantics,
without any catch-all error type.

## Inputs

- Pure domain result/error vocabulary from Effect (`Data.TaggedError` or
  equivalent tagged union).

## Outputs

- Domain failure tags covering the P0 transitions. Frozen names:
  `IdempotencyConflict`, `AuthorityDenied`, `RevisionConflict`. The
  remaining rejection cases are the §12.11 illegal-transition /
  precondition rows; their tag names are **planning-chosen and
  non-canonical** (the design freezes the rejection *set*, not the P0 tag
  strings; exact per-command error contracts are P1, §13).
- `FailureDisposition` ADT with **exactly** the 8 frozen variants
  (§6A.3): `ReturnToCaller`, `RetrySameLogicalCommand`,
  `RetryWithBackoff`, `WaitForStateChange`, `ReconcileBeforeRetry`,
  `SettleExecutionFailed`, `SettleExecutionOutcomeUnknown`,
  `EscalateAttention`. Defining/applying a disposition is Runtime (P1+);
  P0 only fixes the vocabulary.
- A narrow `DomainError` union type (tagged, not a base class catch-all).

## Must Hold

- `Error` ≠ `Outcome` ≠ control flow ≠ `OutcomeUnknown` (§6A.1).
- A normal outcome is not an error; `Blocked != Failed`; Execution failure
  is not Work cancellation; `Verification.Unknown` and unresolved
  Dependency are not failures (§6A.1, §6A.11, §6A.14).
- There is **no** universal `ArborError` (§6A.2).
- The expected-revision mismatch tag is `RevisionConflict`, not a new name
  (§6A.5, §12.5).
- Typed errors carry a stable tag/code so callers can handle narrowly.
- Defects and interruptions are not placed in the expected error channel.
- Adapter-specific errors do not cross into the domain error vocabulary.
- Every failure exposed by P0 transitions is part of a documented union.

## Must Not Decide

- Do not define the `api-contracts` `Problem` DTO (§10.5) — that is a later
  boundary, and `Problem` must never become an internal error type.
- Do not define persistence translation (`PersistenceError`) or runtime
  failure handling (§6A.4, §6A.7–6A.12) — those belong to their owning
  packages.
- Do not model recovery, retry, or transaction behavior.

## Acceptance

- `DomainError` is a closed tagged union with stable tags.
- `FailureDisposition` has exactly the 8 frozen variants (exhaustive
  switch with a `never` default).
- No symbol named `ArborError` or a base error class exists (exported
  allowlist test).
- Type-level test: an unlisted failure cannot be constructed.
