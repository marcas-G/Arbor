# P6-003 — FormationProposal governance + revision-bound RecordDecision (D1)

## Source

- P6 `01` §4.1/§4.2; DID §12.10（RecordDecision→DecisionRecorded, supersede）; P6 `03` §3

## Depends On

- P6-002

## Objective

Implement first-layer gate semantics: proposal admission (Pending, revision=1), `modify` → revision+1 (supersede record, no history rewrite), approve/reject terminal states.

## Outputs

- Governance Runtime admission path + `RecordDecision` handler for FormationApproval.

## Must Hold

- `expectedProposalRevision` mismatch → `DomainError.RevisionConflict`.
- Approve/reject emit `DecisionRecorded` only — no Workspace mutation (D1).
- RecordDecision authority is `AuthenticatedHuman`; terminal proposals reject further decisions.

## Must Not Decide

- No create execution (P6-004); no deep-layer path (P6-005).

## Acceptance

- Stale/terminal/duplicate decision rejections are typed; modify supersedes without rewrite.
