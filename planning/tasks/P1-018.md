# P1-018 — Domain artifact evolution (CommandResolution / CommandReceipt / fingerprint)

## Source

- `docs/design/implementation/P1/01-command-contracts.md` §2, §4
- `docs/design/implementation/P1/03-transaction-model.md` §7
- DID v1.6 §6A.15, §4.1

## Depends On

- P0-001 (`@arbor/domain`)

## Objective

Evolve the P0 domain command artifacts so the frozen P1 contracts compile
before any ports task.

## Outputs

- Parameterize `CommandResolution<Result, Rejection>` and
  `CommandReceipt<Result, Rejection>` in `packages/domain/src/command.ts`
  (P0 shipped single-parameter versions).
- Remove/relocate the interim FNV-1a `semanticRequestFingerprint` from the
  domain (the SHA-256 v1 fingerprint is Application-owned, P1-009).
- Update the affected P0 tests (`packages/domain/test/command.test.ts`,
  `invariants.test.ts`).

## Must Hold

- `CommandResolution` / `CommandReceipt` are **domain-owned generic** types
  with no concrete rejection; Domain does not import `CommandRejection`.
- `ports` can reference `CommandReceipt<unknown, unknown>` without a
  `ports → application` edge.
- No domain lifecycle/semantic change beyond the parameterization.

## Must Not Decide

- No ports/application code.
- No gateway or SHA-256 implementation (P1-009).

## Acceptance

- `packages/domain` compiles with the parameterized types.
- P0 command/invariant tests updated and green.
- `ports` can import `CommandReceipt<unknown, unknown>` without application.

## Verification

```bash
pnpm typecheck
pnpm test command
pnpm check
```
