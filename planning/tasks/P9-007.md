# P9-007 — Lease expiry injection + pre-dispatch T4 proof (L1–L4)

## Source

- P9 `02` §3 (L1–L4); `03` §2 (T4 targeted pre-dispatch check, prohibition restated); P2 `03` §5.1 (QuiescenceControlMutation fencing), §7; DID v1.11 §12.11

## Depends On

- P9-003, P9-004

## Objective

The lease-expiry injection matrix and the mechanical proof that the
pre-dispatch check (T4) is the fence predicate only — never a recovery pass.

## Outputs

- `p9-lease-expiry` suite.

## Must Hold

- **L1**: TTL expires; old worker attempts SettleExecution → fence predicate `expires_at > now` fails → `FencingRejected`; settlement via `QuiescenceControlMutation` is still fenced; the Execution is not settled by the stale worker.
- **L2**: renewal boundary — renewal CAS succeeds (generation unchanged), commit lands before new expiry → the fenced write commits; ownership continuous.
- **L3**: renewal attempted after invalidation/takeover → renewal CAS fails (stale generation / no live lease); the worker stops durable mutation; no ordinary retry.
- **L4**: expiry observed, no takeover yet → invalidation **never settles** the Execution (DID §12.11); stays Active until re-dispatch or deterministic recovery settlement.
- **T4 proof (GQ3)**: the pre-dispatch check performs the lease-fence predicate read only — asserted via nine-step side-effect counters = **0** (no settle attempts, no wake minting, no timer clears, no Attention facts, no reevaluation mutations from the check path); "targeted" wording reserved for T4 only.
- TTL value empirical; the predicate and prohibition are contract.

## Must Not Decide

- No lease CAS / lazy-invalidation / release semantics changes; no TTL numerics as contract; no nine-step-in-dispatch under any flag; no new pre-dispatch checks beyond the fence predicate.

## Acceptance

- L1–L4 mechanically checked (crash-injected class); T4 side-effect count = 0 mechanically asserted.
