# P1-009 — `CommandGateway` + fingerprint

## Source

- `docs/design/implementation/P1/01-command-contracts.md` §2, §3, §4, §8
- `docs/design/implementation/P1/03-transaction-model.md` §3, §4
- DID v1.6 §4.1, §6A.15, §12.3, §12.5

## Depends On

- P1-002 (`ports` contracts)
- P1-004 (transaction)
- P1-006 (`CommandStore` / `DomainEventJournal`)

## Objective

Create `packages/application` with the `CommandGateway` implementing the
generic command pipeline and the frozen fingerprint.

## Outputs

- `packages/application` package.
- `CommandGateway.execute(envelope, submissionContext)` implementing:
  fingerprint → single-tx resolution → idempotency → fence/stop → authority →
  transition → receipt → events.
- `semanticRequestFingerprint`: canonical JSON v1 + SHA-256,
  `FINGERPRINT_ALGORITHM_VERSION = 1`.
- `CommandRejection` (Application-owned); `CommandResolution<Result, Rejection>`
  is domain-owned (P1-018) and only instantiated here.
- Decode `CommandReceipt<unknown, unknown>` (ports) into
  `CommandReceipt<R, CommandRejection>`.
- Replay: existing receipt; fingerprint mismatch → `IdempotencyConflict`
  (deterministic response, no row overwrite).

## Must Hold

- Domain never depends on `CommandRejection` (DID §6A.15).
- Fingerprint input: commandType, projectId, declared actor, schemaVersion,
  semantic payload.
- Idempotency compares `(fingerprint, schema_version, algorithm_version)`.
- Terminal rejection persists a `TerminalRejected` receipt (no event).
- Fence and stop are two checks; fence/stop rejections are terminal receipts.
- `TransactionOperationalFailure` produces no receipt.
- The fence/stop hook is present and **stub-tested** (inert for
  `External`/`System`; a stub distinguishes `FencingRejected` from
  `ExecutionStopping`).

## Must Not Decide

- No P1 command-specific payloads (P1-010..012).
- No lease lifecycle (P2).
- No changes to the fingerprint algorithm.

## Acceptance

- Fingerprint stable under key reorder; differs on semantic change.
- Same id + same fingerprint → existing receipt; different → `IdempotencyConflict`.
- Terminal rejection durable, no event.
- Fence/stop stub test passes (inert External/System path; stub distinguishes
  `FencingRejected` from `ExecutionStopping`).
- `pnpm architecture` green (application → domain, ports).
