# P1-002 — `ports` package: Effect service contracts

## Source

- `docs/design/implementation/P1/02-port-contracts.md`
- DID v1.6 §7.1–§7.4, §7.7, §10.4.1, §6A.2

## Depends On

- P0-001 (`@arbor/domain`)
- P1-017 (harness wiring)

## Objective

Create `packages/ports` with the frozen Effect service contracts. No adapter
implementations.

## Outputs

- `TransactionScope` (`Context.Tag`, carries `AdapterSession`), `TransactionPort`.
- Repositories: `ProjectRepository`, `WorkspaceRepository`, `WorkRepository`,
  `SessionRepository`, `ResourceOwnershipRepository`.
- `CommandStore`, `DomainEventJournal`, `ConsumerOffsetStore`,
  `ConsumerDeadLetterStore`, `EnvironmentRevisionStore`, `ProjectionStore`,
  `OwnershipWriteService`.
- `Clock`, `IdGenerator`, `ProjectEnvironmentPort`.
- Opaque `AdapterSession` type owned by `ports` (must not reference `adapters/*`).
- Per-repository narrow error types (no catch-all `RepositoryError`).

## Must Hold

- Each service declares exact `Effect<A, E, R>`; `R = TransactionScope` for
  transactional repositories (tag enters `R` at the call site).
- `TransactionPort.transact` adds `TransactionOperationalFailure`.
- No universal `RepositoryError`; adapter errors translated at the boundary.
- `ProjectEnvironmentPort.resolve(projectId, addresses)` returns
  `{ regions, observedEnvironmentRevision }`.
- `ports` depends only on `domain` (DID §10.4.1).

## Must Not Decide

- No SQL / adapter code.
- No command handlers.
- No new methods beyond `02-port-contracts.md`.

## Acceptance

- All services compile with the frozen signatures.
- Type-level tests assert the `R` channel (only `TransactionScope`).
- No catch-all error type exists.
- `pnpm architecture` green.

## Verification

```bash
pnpm test p1-ports
pnpm architecture
pnpm check
```
