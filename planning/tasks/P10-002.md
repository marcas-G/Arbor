# P10-002 — api-contracts package + ProjectionQueryPort signature + freshness types

## Source

- P10 `05` §1 (signature freeze + minimal per-view shapes, BLK-3 fix), §3 (transport boundary); P10 `03` §2 (watermark/lag/barrier contract); DID v1.13 §7.2 (ProjectionQueryPort), §10.4.1 (api-contracts deps domain), §10.5 (Problem DTO), §8.19 (FreshnessRequirement vocabulary)

## Depends On

- P10-001

## Objective

Create the `api-contracts` package (deps: domain only) as the
transport-neutral contract surface P12 will bind to: the frozen
`ProjectionQueryPort` signature, the per-view request/response cores, the
watermark/lag result envelope, and the freshness barrier types.

## Outputs

- `api-contracts` package; port signature + `QueryResult`/`ProjectionQueryError` (Problem DTO vocabulary); per-view DTO cores per `05` §1; freshness types; `p10-api-contracts` suite; architecture edge for the new package.

## Must Hold

- Port signature exactly per `05` §1: `query(view, request, barrier?) → Effect<QueryResult<Res>, ProjectionQueryError>`; `QueryResult` carries `{value, watermark, lag}` (GQ5 — every response).
- Errors use the frozen Problem DTO vocabulary (DID §10.5) — stable codes, no message parsing.
- Per-view cores frozen per `05` §1: TreeViewReq/AttentionReq/WorkspaceDetailReq/CurrentWorkReq/VerificationReq/DependencyReq/TranscriptReq/UsageReq/InboxViewReq — these shapes are the contract; row limits/cursors beyond Transcript's are transport concerns (P12).
- Barrier: `{minWatermark}` (GQ5 frozen form) or `{maxLag}` — **maxLag is marked as a contract-level extension** of the GQ5 barrier (a watermark expressed as acceptable lag; same mechanism, no new semantics); reuses the DID §8.19 `FreshnessRequirement` vocabulary at the projection boundary; P3/P4 action-admission semantics untouched.
- `api-contracts` deps **domain only** (DID §10.4.1) — architecture-enforced.
- ViewId enumeration = `01` must-set (Search absent).

## Must Not Decide

- No transport protocol/auth choices (P12); no projection implementations (P10-003+); no RYW semantics; no field-level rendering details beyond the frozen cores.

## Acceptance

- Schema field-presence + round-trip tests for every DTO core; architecture test pins the dependency edge; barrier variant switch exhaustive.

```bash
pnpm test p10-api-contracts
pnpm architecture
pnpm check
```
