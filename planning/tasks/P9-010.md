# P9-010 — Consumer offset wiring + crash/poison matrix (CC-1..CC-6)

## Source

- P9 `05` §1 (offset wiring, dual-guarantee semantics, offset-loss assertion), §2 (CC-1..CC-6); `02` §7 (CC1–CC4); P1 `05` §3–§4 (offset + projection + dead-letter same transaction); P7 `04` §2; P8 `03` §1–§2

## Depends On

- P9-001

## Objective

Wire the P7 coordinator and P8 consumers A/B onto the P1 consumer
infrastructure (`runConsumerBatch` + `ConsumerOffsetStore` +
`ConsumerDeadLetterStore`), retire the direct event-array invocation, and
inject the consumer crash/poison matrix with the dual-guarantee assertion.

## Outputs

- Consumer wiring (P7 coordinator + P8 consumers A/B) + `p9-consumer-crash` suite.

## Must Hold

- **Wiring frozen**: apply-then-advance in ONE transaction (P1 `05` §4); the direct event-array invocation is retired; poll-driven form (loop interval, batch size, dispatcher placement) is a task-level choice.
- **Dual guarantee**: primary = `consumer_offsets.last_sequence` keyed `(consumer_id, project_id)`, never deleted; fallback = deterministic CommandId idempotency (CommandReceipt, P1 `01` §8; P7 `04` §2; P8 `03` §1–§2).
- **Offset loss / regression injection**: delete or regress the offset row → the consumer re-delivers from the effective retained floor → every re-submitted Event→Command is absorbed by the deterministic CommandId (existing Receipt / typed terminal rejection recorded, no re-burn); canonical state converges; zero duplicate domain effects.
- **CC-1**: mid-batch abort after projection apply, before offset advance → apply + advance are ONE transaction → both roll back → re-run re-delivers and re-applies idempotently (`(project_id, sequence)` key); **the offset NEVER advances without the apply**.
- **CC-2**: offset row deleted / regressed below the true position → `read` returns 0 (absent) or stale → full/stale replay absorbed by id-idempotency; dead-letter re-quarantine is a no-op (PK dedup, `INSERT OR IGNORE`).
- **CC-3**: poison path 1 — `eventVersion` > reader ceiling → quarantine + offset advance past the sequence in the SAME transaction; the consumer never stalls (no head-of-line block); the dead-letter row persists; operator alert.
- **CC-4**: poison path 2 — deterministic handler/projection defect → same poison semantics; **classification rule frozen**: typed `DomainError` rejections are NOT poison (recorded outcomes, P7 `04` §2); deterministic defects (decode/schema/unexpected throw) ARE poison; transient operational failures (busy/IO) abort the batch and retry — never dead-letter.
- **CC-5**: projection failure mid-batch never rolls back the domain command transaction (DID §5.4); consumer-level disposition per CC-3/CC-4.
- **CC-6**: concurrent double-dispatch of one consumer → single-flight per `(consumer_id, project_id)`; `BEGIN IMMEDIATE` serializes; idempotent re-apply makes the overlap harmless.

## Must Not Decide

- No offset / dead-letter schema change (P1 `05` owns); no retention / pruning semantics change (P1 `04` owns the horizon); no new delivery semantics beyond P1 `05`; no external projection stores; no business projection rebuild (P10, GQ2).

## Acceptance

- CC-1..CC-6 and the offset-loss dual-guarantee assertion mechanically checked (crash-injected class); P7/P8 consumer regression suites updated-green on the wired path.
