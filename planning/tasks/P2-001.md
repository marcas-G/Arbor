# P2-001 — P2 package skeletons + harness wiring

## Source

- DID v1.7 §10.4.1 (package DAG), §11 P2; P1-017 (harness)

## Depends On

- P1-016

## Objective

Create the P2 packages/adapters and wire the build/test harness so the kernel has a home.

## Outputs

- `packages/execution-runtime` skeleton (package.json, tsconfig, `src/index.ts`).
- `packages/agent-runtime` skeleton (driver seam; real loop is P3). The P2 skeleton must **not** depend on the not-yet-existing `model-context` package; the edge is added in P3.
- `packages/testkit` skeleton (test doubles).
- `adapters/worker-local` skeleton.
- Root `tsconfig.json` references; `tests/architecture/package-dag.ts` adapter key `worker-local`.

## Must Hold

- Package DAG per DID §10.4.1: `execution-runtime -> domain, ports, application, agent-runtime`; `agent-runtime -> domain, ports, application, model-context`; `testkit` test-only; `adapters/* -> domain, ports`.
- `runtime !-> adapters`; `adapters !-> runtime`.
- New packages are covered by `readPackages` automatically.

## Must Not Decide

- No behavior, no services, no DDL.
- No weakening of the architecture matrix.

## Acceptance

- `pnpm build` / `pnpm typecheck` green with the new packages.
- `pnpm architecture` recognizes `execution-runtime`, `agent-runtime`, `testkit`, `worker-local`.

## Verification

```bash
pnpm test p2-harness
pnpm check
```
