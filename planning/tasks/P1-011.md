# P1-011 — `CreateChildWorkspace` handler

## Source

- `docs/design/implementation/P1/01-command-contracts.md` §6
- `docs/design/implementation/P1/04-sqlite-schema.md` §3.1
- DID v1.6 §11 (P1), §12.11 Workspace

## Depends On

- P1-005 (repositories)
- P1-006 (CommandStore / DomainEventJournal)
- P1-009 (CommandGateway)

## Blocked By

None (P1-DG-11 RESOLVED — authority is a trusted Application input fact,
`01-command-contracts.md` §2A).

## Authority

- `VerifiedCommandAuthority` tag `CreateChildWorkspaceAuthority`; exact-match on
  principal, commandId, fingerprint, projectId, and
  `parentWorkspaceId == payload.parentWorkspaceId`.
- Mismatch → `AuthorityDenied`; no default-allow.

## Objective

Implement `CreateChildWorkspace`: create a child Workspace + its
`WorkspacePrimary` Session in one transaction.

## Outputs

- `CreateChildWorkspacePayload` and handler.
- Result `{ workspaceId, projectId, parentWorkspaceId, primarySessionId }`.
- Event `WorkspaceCreated`.

## Must Hold

- Parent must exist in `envelope.projectId` (`WorkspaceNotFound` /
  `AuthorityDenied`).
- Parent lifecycle Active else `TerminalLifecycleMutation`.
- `parentWorkspaceId` immutable; child inherits project.
- Child Session created atomically; no Session event.
- `basisResponsibilityRevision == responsibilityRevision` else `AuthorityDenied`.

## Must Not Decide

- No reparent/move.
- No responsibility formation prompt (P6).

## Acceptance

- Child created with correct parent/project; Session created atomically.
- Retired parent / foreign project rejected.
- Replay returns existing receipt.

pnpm test p1-create-child-workspace
