# P0-017 — Package DAG architecture tests

## Source

- DID §10.4 Dependency Rules
- DID §10.4.1 Allowed internal dependency matrix
- DID §10.3 Effect Boundary
- DID §14.5 criterion 14
- `AGENTS.md` hard rule 5

## Depends On

- P0-001

## Objective

Implement the Vitest architecture tests that enforce the allowed package
dependency DAG and the domain purity rule. The matrix checker must be
exercised even though P0 has a single package.

## Inputs

- Workspace package manifests and `exports` maps.
- The allowed-edge matrix from §10.4.1.

## Outputs

- Architecture test entry under `tests/architecture/` that:
  - reads each package's declared internal dependencies;
  - asserts every edge is allowed by §10.4.1, and that unlisted internal
    edges are forbidden;
  - asserts `domain` declares **no** internal dependency and imports no
    infrastructure;
  - asserts no deep imports bypassing `exports`;
  - encodes the extra hard rules: `adapters !-> application/runtime`,
    `runtime packages !-> adapters`, `model-context !-> tool-runtime`, etc.
- A **committed unit test of the matrix-checker function** fed synthetic
  package manifests, including at least one forbidden edge and one unknown
  package, so the checker is proven to fail on violations even when only
  `packages/domain` exists.

## Must Hold

- `domain` has no infrastructure dependency and no internal dependency.
- Canonical semantic mutation only through Application (checked once
  `application` exists; absent packages are skipped explicitly, not
  silently passing violations).
- Runtime depends on Ports, not Adapters.
- Composition happens only at the app boundary.
- Projection never participates in authority decisions.
- The matrix is data-driven so new packages are covered automatically.
- The checker itself is unit-tested with synthetic manifests.
- No global `AppEnv` / `RuntimeContext` / service locator.

## Must Not Decide

- Do not weaken the matrix to accommodate an inconvenient edge; a needed
  new edge requires proving it is not an inward composition/implementation
  leak (§10.4.1), i.e. a design change.
- Do not implement package-level behavior; tests are structural only.
- Do not add a second architecture-test root; `tests/architecture/**` is
  canonical.

## Acceptance

- `pnpm architecture` is green for the P0 package set.
- The synthetic-manifest unit test fails on a forbidden edge and on an
  unknown package (proves the checker is non-vacuous).
- `domain` is proven dependency-free.

## Verification

```bash
pnpm architecture
pnpm test -- architecture
pnpm check
```
