# P7-005 — SatisfyDependency handler (exact-bound authority, matcher, wake production)

## Source

- P7 `01` §4, `04` §5, `06` §2; DID v1.10 §1.8, §5.4, G6

## Depends On

- P7-002, P7-003

## Objective

The single Dependency-satisfaction command face: handler with the frozen rejection table, exact-bound `SatisfyDependencyAuthority`, deterministic automatic-path CommandId, and same-transaction `DependencyChanged` wake production.

## Outputs

- Command handler + consumer-side directive (`ConsumerExecution` authority).

## Must Hold

- **Exact-bound authority (G6)**: source is exactly `ConsumerExecution | P7Coordinator`; anything else → `AuthorityDenied`. The fact binds (dependencyId, deliverableId).
- **Single command face**: agent path and coordinator path submit the same Command, hit the same handler and rejection table, are gated by the same frozen matcher (`matchesExpectedDeliverable`) — no agent-path exemption; request ≠ satisfaction.
- Matcher false → `DependencyNotSatisfiable`, state unchanged; Project boundary precedes the matcher (`AnyProducer` must not cross Projects).
- Concurrency: two deliverables racing → first committer wins (state + revision CAS); loser receives the typed rejection matching its observation (`TerminalLifecycleMutation` / `RevisionConflict` / `DependencyNotSatisfiable`).
- Commit boundary: state CAS + `DependencySatisfied` + wake production share one transaction; wake fires only when `observedRevision < new revision`; `WakeReason` not extended — payload in the delivery record.
- Satisfaction records are immutable — later revisions never reinterpret them (`satisfiedAtDependencyRevision`).

## Must Not Decide

- No matcher / algorithm changes; no coordinator trigger or lookup semantics (P7-009); no consumer-side wake routing (P7-011).

## Acceptance

- Rejection table, CAS race outcomes, and the wake commit boundary are mechanically checked.

pnpm test p7-satisfy-dependency
