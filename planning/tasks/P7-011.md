# P7-011 — Wake consumption pipeline + composition P7_MIGRATIONS

## Source

- P7 `06` §1–§3; DID v1.10 §8.16/§8.18; SD v1.3 §7.6, No.53

## Depends On

- P7-005

## Objective

Close the wake consumption side: wakeReason routing in `reevaluate`, a unified wake sink, `clearWorkWait` wiring, and the composition upgrade to P7_MIGRATIONS (fixing the P6-era P4_MIGRATIONS residue).

## Outputs

- Routing table + wake sink + `clearWorkWait` calls + `P7_MIGRATIONS` composition.

## Must Hold

- Routing: `DependencySatisfied` → the consumer Work's Workspace; other reasons → the reason-carried target; `ChildDelivered` is produced at the Deliver delivery boundary (P7-007).
- Contract freezes only: after event commit, `reevaluate` is eventually triggered at least once — at-least-once, idempotent. Daemon-lite background fiber vs synchronous pipeline is an implementation choice.
- `reevaluate` clears WorkWaits for Works it finds runnable (P2 frozen mechanism, first correct wiring).
- Wake payloads (`dependencyId`, `fromRevision`, `toRevision`) live in the wake signal delivery record; no new `WakeCondition` / `WakeReason` variants; no cross-Project wake; no model polling (No.53).
- Composition uses **P7_MIGRATIONS**; the migration-set upgrade also fixes the P6-era P4_MIGRATIONS residue.

## Must Not Decide

- No WorkWait / timer mechanism changes (P2); no scheduler decision-table changes.

## Acceptance

- wake → reevaluate → runnable restoration end-to-end with observedRevision progression; dead/looping wakes are idempotent no-ops; migration-set upgrade applies cleanly.

pnpm test p7-wake-pipeline
