# P1-003 — P1 DDL migrations

## Source

- `docs/design/implementation/P1/04-sqlite-schema.md` §3, §4, §6
- DID v1.6 §9.3, §9.13, §12.11

## Depends On

- P1-001

## Objective

Write the P1 DDL migration creating every P1 table with deferred FKs,
constraints, and indexes.

## Outputs

- `migrations/0001_init.sql` creating: `projects`, `workspaces`, `sessions`,
  `works`, `resource_ownership`, `environment_revisions`, `commands`,
  `command_attempts`, `domain_events`, `project_event_sequences`,
  `consumer_offsets`, `consumer_dead_letters`.
- Deferred composite FKs (`(root_workspace_id, project_id)`,
  `(parent_workspace_id, project_id)`), `UNIQUE(workspace_id, project_id)`.
- Partial indexes (`resource_ownership` active, by space and by workspace).
- CHECK constraints (lifecycles, resolution/result/error exclusivity,
  `released_at >= created_at`).
- Fence/stop predicates documented (tables are P2).

## Must Hold

- `commands.resolution ∈ {Committed, TerminalRejected}`; no `Pending`.
- `commands` / `domain_events` / `consumer_offsets` retention rules per `04` §6.
- `project_event_sequences` is a durable counter (not derived from events).
- Deferred FK cycles commit atomically for the bootstrap.
- No physical SQL overlap approximation columns.

## Must Not Decide

- No P2+ tables (`executions`, `execution_leases`, `verifications`, …).
- No index/query optimization beyond `04`.

## Acceptance

- Migration applies cleanly on an empty DB.
- Bootstrap insert order (project → root workspace → session) commits under
  deferred FKs; cross-project root/parent rejected at COMMIT.
- CHECK violations rejected (resolution/result mismatch, negative release).
- Partial indexes exist.
