# P9-008 — Provider disconnect + unsettled Turn recovery (PD1–PD4 / I-4..I-7; GQ4)

## Source

- P9 `02` §6 (PD1–PD4), `04` §2 (§2.1 zero-new-tag mapping, §2.2 unsettled-ProviderTurn recovery, §2.3 assertions I-4..I-7); P3 `06` §2 (retryable/terminal mapping), P3 `01` §4–§5 (Turn/Attempt identity, UsageReported), P3 `04` §3 (persisted Turn intent); DID v1.11 §6A.8/§6A.9, §9.8; GQ4 adjudication

## Depends On

- P9-001, P9-003

## Objective

Land GQ4: inject disconnect scenarios mapped onto the existing
`ProviderFailureKind` (zero DID change) and own the P9-frozen
unsettled-ProviderTurn crash recovery face (P3 `06` §7 explicitly deferred it
here).

## Outputs

- `p9-provider-disconnect` suite.

## Must Hold

- **Mapping frozen (zero new tags)**: connect-phase failure → `ProviderUnavailable`; interruption after `TurnStarted` (stream began) → `StreamInterrupted`; both retryable under the P3 `06` §2 safe-retry policy; the harness classifies by the **observable boundary** (`TurnStarted` emitted or not), never by transport errno.
- **PD1 / I-4**: disconnect pre-connection → `ProviderAttempt.outcome = RetryableFailure`, `provider_error_kind = ProviderUnavailable`; no new ProviderTurn issued; `turnNo` unchanged.
- **PD2 / I-5**: disconnect mid-stream → `StreamInterrupted`; retried under the **SAME Turn**; `turnNo` unchanged across attempts; attempt history append-only; no partial Session entry (streaming deltas never enter Session history, DID §9.8 — resume is clean by construction).
- **PD3**: terminal classes (AuthenticationFailed / RequestRejected / ProtocolViolation) → no transport retry; Attention where required; a terminal Turn failure does **not** itself settle Execution `Failed` — the driver decides bounded retry/repair vs settle after exhaustion.
- **PD4 / I-7 — same Turn, new Attempt, turnNo unchanged**: daemon crash leaves `provider_turns.settled_at IS NULL` (Turn intent + Manifest persisted before the request, so the dangling Turn is always visible) → resume-by-retry: same ProviderTurn, new ProviderAttempt (`attempt_no = MAX+1`, Turn-local); Agent `turnNo` unchanged; no new Manifest — a resumed Turn is a transport retry, not a new model decision; transport retry is never recorded as an extra model round (DID §6A.9); `UsageReported` aggregates per Turn over attempts.
- The recovery pass itself **never calls the provider**: it leaves the Execution Active; the Scheduler re-dispatches; the driver resumes the dangling Turn under the same `providerTurnId` + `manifestId`.
- **I-6**: bounded retries exhausted → the Turn settles failed under the existing driver Turn-failure semantics; Execution-level disposition follows P2 `06` §4 — recovery never invents a settlement; durable Attention on escalation.
- Provider turns carry no external side effect beyond the provider request itself — tool-style `OutcomeUnknown` ambiguity does not arise (`OutcomeUnknown` is tool-invocation settlement vocabulary, P4 `06`).
- Retry counts / backoff empirical (P3 `06` §3 discipline); the Turn/Attempt identity invariants are contract.

## Must Not Decide

- No new failure tags; no §6A.8 change (GQ4 option a); no P3 retry-bound / backoff modification; no OutcomeUnknown for provider turns; no provider-call-from-recovery under any flag.

## Acceptance

- PD1–PD4 + I-4..I-7 mechanically checked (crash-injected class); `providerTurnId` / `manifestId` / `turnNo` invariants asserted across crash-resume; no-partial-output assertion on mid-stream crash.
