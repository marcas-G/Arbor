# P2-002 — P1/P0 artifact evolution + pointer notes

## Source

- P2 `01` §2.1–§2.3, §3; `02` §4; DID v1.7 G1

## Depends On

- P2-001

## Objective

Evolve the P0/P1 artifacts P2 requires, and add pointer notes in the P1 contracts.

## Outputs

- `domain`: `CommandSubmissionContext` gains `RecoveryController { principal, causationRef }`.
- `application` (`rejection.ts`): `CommandRejection` gains Application-owned `ExecutionNotFound { executionId }`.
- `application` (`authority.ts`): add `VerifiedRuntimeCommandAuthority` (Admit/Stop/Settle variants per `01` §2).
- `application` (`gateway.ts`): authority parameter generalized to `CommandAuthorityFact = VerifiedCommandAuthority | VerifiedRuntimeCommandAuthority`; `CommandHandler` gains `stopAdmission: StopAdmission` (ADT).
- `application` (`gateway.ts`): `FenceStopCheck.check(context, stopAdmission)`.
- Pointer notes in `docs/design/implementation/P1/01-command-contracts.md` §2/§3 and `03-transaction-model.md` §4.

## Must Hold

- The three P1 authority variants and the P1 exact-match rule are unchanged.
- `ExecutionNotFound` is Application-owned and never appears in `DomainError`.
- `stopAdmission` is an explicit ADT (`NormalExecutionMutation | QuiescenceControlMutation | StopControl | Unclassified`), never a boolean.
- P1 handlers remain valid (default `Unclassified`; fence hook inert for External/System).

## Must Not Decide

- No new Domain Event types.
- No change to the P1 fingerprint or idempotency semantics.
- No P1 semantic change beyond the frozen evolutions listed in the P2 index.

## Acceptance

- P1 test suite still green after the evolution.
- Type-level test proves `ExecutionNotFound` is not a `DomainError` and `stopAdmission` is not a boolean.
- `CommandAuthorityFact` accepts both P1 and P2 facts.
