# P1-001 — SQLite adapter, connection settings, migration mechanism

## Source

- `docs/design/implementation/P1/04-sqlite-schema.md` §1, §5
- DID v1.6 §9.1 (WAL / foreign_keys / busy_timeout / short transactions)

## Depends On

- P1-017 (harness wiring)

## Objective

Fill the `adapters/persistence-sqlite` skeleton (created by P1-017) with the
frozen connection settings and a forward-only migration runner. No tables yet
(P1-003).

## Outputs

- `adapters/persistence-sqlite` package (Layer opening the SQLite connection).
- `Clock` and `IdGenerator` adapter Layers.
- Connection settings: `journal_mode=WAL`, `foreign_keys=ON`,
  `busy_timeout=5000`, `synchronous=FULL`.
- Migration runner: `PRAGMA user_version`, forward-only ordered
  `migrations/NNNN_*.sql`, refuse to start if `user_version` > latest known;
  additive migrations in one transaction; table-rebuild exception documented.

## Must Hold

- Settings are applied per connection.
- Requires SQLite ≥ 3.35 (`RETURNING`, `ON CONFLICT ... DO UPDATE`).
- Migration failure leaves `user_version` unchanged.
- Adapter-specific errors never cross the port boundary (translated later).

## Must Not Decide

- No P1 tables (P1-003).
- No repository/port implementations.
- No changes to the frozen settings.

## Acceptance

- Adapter Layer opens a DB with the four PRAGMAs verified.
- `Clock`/`IdGenerator` have deterministic test Layers.
- Migration runner applies a trivial test migration and sets `user_version`
  (the real P1 DDL is `0001_init.sql`, owned by P1-003).
- A newer `user_version` makes startup refuse.
- `pnpm architecture` still green (adapter depends only on `domain`/`ports`).

## Verification

```bash
pnpm test p1-sqlite-adapter
pnpm architecture
pnpm check
```
