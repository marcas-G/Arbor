## Objective

The GQ2 P9 face — generic projection recovery/rebuild assertions over

whole phase.

## Outputs

## Must Hold

- **RB-1 floor refusal**: offset < pruned floor (`MIN(domain_events.sequence)`) → typed refusal `ConsumerRebuildRefused{offset, floor}`; no partial reset, no state destruction.
- **RB-2 reset atomicity**: projection reset + offset rewind to floor in ONE transaction; abort mid-rebuild leaves either the pre-reset or the post-reset state, never a hybrid.
- **RB-3 replay idempotency**: re-running rebuild to completion is a no-op delta: `(project_id, sequence)` INSERT OR IGNORE → at-most-once projection rows; re-quarantine is a PK no-op.
- **RB-4 rebuildability**: with intact `domain_events` up to the retention horizon, rebuild always reaches the same projection state (P1 `05` §6 — append-only before the horizon).
- **RB-5 degenerate**: zero-events project → floor 0, replay 0, success.
- **PR1–PR4** (`02` §10 — same semantics as `05` §3 at coarser grain; divergence between the two documents is a defect): offset-row-loss replay from pruned floor converges (no duplicates); explicit reset to floor in `(project_id, sequence)` order; sub-floor rebuild refused (typed, no silent partial rebuild); replay idempotency never rolls back domain transactions (No.37).
- **Evidence protocol (`02` §12, frozen)**: DA1 (OS/power loss after COMMIT → committed durable) and DA2 (crash during WAL checkpoint → prior committed txs durable) are **durability-asserted, NOT crash-injected** — P9 never simulates them; evidence per daemon restart / suite run:
  1. `synchronous = FULL` + WAL active (P1 `04` §1; No.60);
  2. reopen succeeds; `PRAGMA integrity_check` = ok;
  3. `PRAGMA user_version` == frozen migration baseline (P1 `06` §5);
  4. count reconciliation across core tables (`executions`, `execution_leases`, `domain_events`, `commands`, `consumer_offsets`) consistent with fixture;
  5. result recorded with the explicit "durability-asserted" label.
- **Labeling obligation (GQ5)**: every result row across the p9-* suites carries exactly one guarantee class; a durability-asserted result is **never claimed as crash-injected**; claims are bounded by the declared `DurabilityEnvelope` (DID §9.1; SD §10.7) — storage-media / region loss is outside and reported truthfully (P2 `06` §7).
- **P10 boundary (GQ2)**: no business-projection rebuild (InboxProjectionStore, Attention views, wait-graph derived views) is built or asserted here — negative assertion in suite.

## Must Not Decide

- No at-scale rebuild orchestration / incremental checkpoints / per-projection retention (P10); no retention-horizon change; no fault-injecting SQLite adapter (GQ5 option (b) declined); no offset/dead-letter schema change.
