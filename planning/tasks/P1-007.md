# P1-007 — Resource ownership + environment revision + resolver

## Source

- `docs/design/implementation/P1/02-port-contracts.md` §3, §4, §6
- `docs/design/implementation/P1/04-sqlite-schema.md` §3.3
- DID v1.6 §9.5, §1.5

## Depends On

- P1-003 (DDL)
- P1-004 (transaction)

## Objective

Implement resource-ownership persistence and the environment resolver.

## Outputs

- `ResourceOwnershipRepository` (`loadActiveConflicts`, `insertClaim`,
  `releaseClaim`, `listActiveByWorkspace`).
- `EnvironmentRevisionStore` (`current` → `Option`, `record`).
- `ProjectEnvironmentPort` adapter (`adapters/environment-local`) returning
  `{ regions, observedEnvironmentRevision }`.
- `OwnershipWriteService.resolveAndWrite` implementing the 04 §3.3 sequence.
- Frozen `normalizedRegion` encoding per resource kind.

## Must Hold

- Release is `UPDATE ... WHERE released_at IS NULL`; rows never hard-deleted.
- Ownership write: resolve outside tx → `BEGIN IMMEDIATE` → stale re-check via
  `EnvironmentRevisionStore.current` → `loadActiveConflicts` → domain
  `overlaps()` → insert/release → `record` → COMMIT.
- `environment_revisions` lazy init; `None` = not stale.
- The write compares the observed environment revision
  (`resolved_at_environment_revision`) and the basis responsibility revision
  before committing (04 §3.3 CAS columns).
- Overlap evaluated by the domain function, never SQL string prefix.
- `ResourceResolutionStale` is an operational failure (re-resolve).

## Must Not Decide

- No new overlap semantics (domain-owned).
- No environment-change command (later phase).
- No query optimization beyond `04`.

## Acceptance

- Conflicting claim rejected by domain overlap; stale environment revision →
  `ResourceResolutionStale`.
- `releaseClaim` is idempotent (`WHERE released_at IS NULL`).
- `record` populates `environment_revisions` on first successful write.
