# P1-012 — `AssignWork` handler

## Source

- `docs/design/implementation/P1/01-command-contracts.md` §7
- `docs/design/implementation/P1/04-sqlite-schema.md` §3.2
- DID v1.6 §0A.1, §6A.15, §12.10, §12.11 Work

## Depends On

- P1-005 (repositories)
- P1-006 (CommandStore / DomainEventJournal)
- P1-009 (CommandGateway)

## Objective

Implement `AssignWork`: create an `Open` Work bound to a Workspace.

## Outputs

- `AssignWorkPayload` and handler.
- Result `{ workId, workspaceId, lifecycle: "Open", revision }`.
- Event `WorkAssigned`.

## Must Hold

- Rejections per `01` §7: `WorkspaceNotFound`, `AuthorityDenied` (foreign
  project / no authority / scope), `TerminalLifecycleMutation` (Project closed
  / Workspace retired), `RevisionConflict` (workspace revision).
- `workspace.projectId == envelope.projectId`.
- All ids caller-preallocated; handlers never generate ids.
- P0 `assignWork` `RetirePreconditionFailed` branch superseded by
  `TerminalLifecycleMutation`.

## Must Not Decide

- No Work lifecycle transitions beyond assignment.
- No scheduler/runnable evaluation (P7).

## Acceptance

- Work created `Open` bound to the workspace; `WorkAssigned` emitted.
- Cross-project / closed project / retired workspace / stale revision rejected
  with the frozen tags.
- Replay returns existing receipt.
