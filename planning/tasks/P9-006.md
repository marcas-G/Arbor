# P9-006 — Worker crash + resurrection injection matrix (W1–W5 / R1–R6)

## Source

- P9 `02` §1 (W1–W5, baseline fixture, W3 takeover note), §2 (R1–R6, fence-in-same-tx note, Work-lifecycle note); DID v1.11 §6.3 (fencing write surface), §6A.5, §6A.6; P2 `03` §1–§3; P1 `06` C3/C4

## Depends On

- P9-001, P9-003

## Objective

The crash-injected worker-crash rows (five injection points from dispatch
accept to settlement window) and the old-worker-resurrection rows (stale
generation writing across the full fencing write surface).

## Outputs

- `p9-worker-crash` suite (W1–W5) + `p9-resurrection` suite (R1–R6).

## Must Hold

- Baseline fixture: admitted Active main Execution; kill via the P9-001 harness at the named point (exact mechanism empirical; the point and the assertion are contract).
- **W1**: kill at dispatch-accepted-before-lease-acquire → no lease row; Execution unchanged (`settled_at IS NULL`); dispatch failure never settles; next sweep reevaluation re-dispatches.
- **W2**: kill after lease acquire, before drive starts → live lease row until TTL; Execution unchanged; no `Active → Settled` transition from crash alone.
- **W3**: kill mid-drive (provider stream / tool effect in flight) → dangling intents detectable (unsettled ProviderTurn / ToolInvocation → §5/§6 semantics); durable state unchanged; lease lazily invalidates; new worker acquires at `generation + 1`; **the takeover worker's first fenced write commits with the new generation AND the old worker's late write of the same logical content is rejected** (single authoritative resolution).
- **W4**: kill after settlement proposal decided, before canonical command COMMIT → nothing durable (writes + event + receipt share one tx, P1 `06` C3/C4); retry/re-dispatch converges; no partial state.
- **W5**: kill after effectful work, before SettleExecution → stays Active; recovery settles only via the durable deterministic trace or leaves Active for re-dispatch; unresolved side effects gate settlement (No.54).
- **R1–R6**: stale-generation (`generation = g` after takeover at `g+1`) attempts across all six write surfaces — Execution semantic mutation → `FencingRejected`; Session append → `LeaseFencingRejected`; ProviderTurn settlement → `LeaseFencingRejected`; ToolInvocation settlement → `LeaseFencingRejected`; Agent-produced canonical command → `FencingRejected`, terminal for that logical Command, no ordinary retry; local uncommitted writes → invisible (fence shares the mutation transaction — no stale write can become durable).
- The fence predicate check runs in the SAME transaction as the write — R1–R5 assert the **authoritative rejection**, not the fast-fail pre-check.
- Neither `LeaseLost` nor `FencingRejected` fails/cancels the Work — Work lifecycle unchanged after all six rows (DID §6A.5).
- Lazy invalidation is the only lease-expiry authority: no worker action is required for takeover.

## Must Not Decide

- No fencing / lease semantics changes; no Work lifecycle coupling; no settle-rule changes; injection mechanism details empirical.

## Acceptance

- Every W/R row ≥1 mechanical crash-injected case with guarantee class labeled; W3 dual-write resolution and the R-row Work-lifecycle invariance explicitly asserted.
