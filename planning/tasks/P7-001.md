# P7-001 — P7 domain evolution (kinds, specs, event payloads)

## Source

- P7 `01` §2/§3/§4/§5–§7/§9, `02` §2/§3/§8, `04` §5, `05` §2; DID v1.10 §5.3, §8.15

## Depends On

- P6-015

## Objective

Freeze the P7 vocabulary as code: `MESSAGE_KINDS` four → five (`"Deliver"`), the `OutboundMessage` Deliver variant, the four directive specs (`DeclareDependency` / `ProduceDeliverable` / `Deliver` / `SatisfyDependency`), the 5+2 event payloads, the exact-bound `SatisfyDependencyAuthority`, and the two new `CommandRejection` enums.

## Outputs

- Domain ADT extensions (communication / dependency / events) + directive spec types.

## Must Hold

- `WakeReason` union unchanged — wake payloads live in the signal delivery record, never in the type (`06` §2).
- `InboxEntry` kind set unchanged — Deliver lands in `"Message"` (`02` §5).
- Authority source is exactly two-valued: `ConsumerExecution | P7Coordinator` (`01` §4, G6).
- Existing four message kinds' semantics unchanged — enumeration growth only (`02` §2).
- Domain stays pure (`R = never`); no infrastructure imports.

## Must Not Decide

- No handler semantics; no DDL; no matcher / state-machine changes (P0 frozen).

## Acceptance

- Exhaustive switches compile; illegal variants fail typecheck; empty-shell lock-down tests updated to cover all seven new events and both rejection enums.

pnpm test p7-domain
