# P0-003 — Scoped ordinals & core value-object primitives

## Source

- DID §2.3 Event ordering & local ordinal
- DID §3.1–§3.6 revision fields
- DID §1.1 Object classification (Value Object / Durable Record rows)
- DID §4.1 (`actor` / `principal` on `CommandEnvelope` / context)
- DID §5.2 (event `actor`)

## Depends On

- P0-001
- P0-002 (branded-type facility)

## Objective

Implement the scoped-ordinal and revision value objects shared by the
aggregate models, plus the small pure primitives they require (including
the shared actor/principal value type). No aggregate state machine is
implemented here.

## Inputs

- Branded-type facility from P0-002.

## Outputs

- Scoped ordinals / counters:
  `ContextEpochNumber`, `LeaseGeneration`, `ResponsibilityRevision`,
  `ResourceBoundaryRevision`, `ArtifactRevision`, `EventSequence`,
  `WorkRevision`, `DependencyRevision`, aggregate `Revision`
  (Project/Workspace).
- `WorkRevision` is the `Work.revision` value type; `DependencyRevision` is
  the `Dependency.revision` value type. Both are scoped ordinals / branded
  values, **not** entity IDs (no prefix, not in §2.1).
- `EventId` vs `EventSequence` kept as separate concepts.
- `Actor` / `Principal` value type(s) used by `Acceptance.actor`,
  `CommandEnvelope.actor`, `CommandSubmissionContext.principal`,
  `DomainEvent.actor`, and `PermissionGrant.issuer`.
- Pure helpers for monotonic increment and comparison.

## Must Hold

- Ordinals are **local**, not globally unique identities.
- `EventSequence` is a Project-local / journal-partition ordering, not a
  UUID and not a timestamp.
- Revisions are monotonically increasing; comparison is total and pure.
- `WorkRevision` / `DependencyRevision` are scoped ordinals, not entity IDs
  and not prefixed.
- No implicit coercion between an ordinal and a typed ID.

## Must Not Decide

- No aggregate lifecycle or transition logic.
- No persistence, sequence allocation, or transaction semantics.
- Do not invent a global sequence service.

## Acceptance

- All listed ordinals exist as branded value objects.
- Increment/compare helpers are pure and total.
- `EventId` and `EventSequence` are distinct types and not interchangeable
  (type-level test).
- `Actor` / `Principal` codec round-trips.
- Round-trip codecs pass.
