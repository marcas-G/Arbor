# P7-010 — Wait-for graph + DeadlockAttentionRequested

## Source

- P7 `05` §1–§2; DID v1.10 §5.3, §6.2, G4; SD v1.3 No.42/55, A3

## Depends On

- P7-008

## Objective

Deterministic wait-for graph (derived view over dependencies × work_waits × works) plus cycle detection emitting `DeadlockAttentionRequested` fact events.

## Outputs

- Pure graph construction + `hasDeadlock` + L4 re-check trigger wiring + fact-event emission.

## Must Hold

- Nodes: Open Works. Edges from `ProducerBinding`: `WorkBound(w)` → node w; `WorkspaceBound(ws)` → fan-out to all Open Works of ws (no synthetic sink node); `AnyProducer` → no edge. An edge is valid only when the consumer Work holds an active `WorkWait(DependencyChanged(dep))`.
- `hasDeadlock(graph)` = a wait-cycle whose members are all blocked (blocking per `03` §2) ∧ no runnable Work in the Project (No.42 is project-scoped; classify is the only authority).
- **Liveness trigger set**: fact commits of DependencyDeclared / WorkWait upsert / DependencySatisfied / DependencyWithdrawn / DependencyMarkedUnfulfillable / DependencyContractRevised / DeliverableProduced — declare-then-yield cycles are caught at the second WorkWait upsert.
- **Zero mutation**: detection emits facts only (`DeadlockAttentionRequested { cycleWorkIds, dependencyIds, detectedAt }` at a reliable commit boundary); no Work/Dependency lifecycle change; escalation stays human/Parent cognition; distinct from the MarkedUnfulfillable Attention fact (No.55).
- Graph is a pure function — no new canonical entity, no new store.

## Must Not Decide

- No auto-resolution; no Attention presentation/UI (P10); no cross-Project graph; no scheduler changes.

## Acceptance

- Mutual `WorkBound` wait cycle emits the fact with cycle members; Work/Dependency state byte-identical before/after detection; resolution emits a fresh fact, never a rewrite.
