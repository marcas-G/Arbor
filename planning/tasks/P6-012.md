# P6-012 — Critical Steer quiescence wiring

## Source

- P6 `04` §4; SD §7.3（Stop/Critical Steer quiescence）; DID §3.4; P2 `01` §6

## Depends On

- P6-011

## Objective

Wire Critical Steer: `SteerWork(Critical)` + `StopExecution(当前 active main)` in one reliable commit boundary.

## Outputs

- Composite governance submission + recovery-safe ordering.

## Must Hold

- Same commit boundary for `WorkSteered` + stop request; no new ProviderTurn/ToolInvocation/canonical command/spawn after commit（DID §3.4）.
- Work stays Open; steer never implicitly cancels（`CancelWork` 分离）.
- Next admission reinjects Control face per DID §8.13（Constraints/Current Work）.
- Safety-Envelope interruptions remain a separate channel（归因不混用）.

## Must Not Decide

- No quiescence mechanism changes (P2 owns); no Critical auto-detection.

## Acceptance

- Quiescence observable via execution action count; Work Open + self-resume after reevaluation（S2 §7）.

```bash
pnpm test p6-critical-steer
pnpm check
```
