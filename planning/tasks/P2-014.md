# P2-014 — `WorkerDispatchPort` + `ExecutionDriverPort` + `FakeDriver` + `RuntimeSafetyGate`

## Source

- P2 `02` §5, `05` §7; DID v1.7 §8.16A, §10.6, G4

## Depends On

- P2-002
- P2-009

## Objective

Implement worker dispatch, the driver seam, the Fake Driver and execution-wide Runtime Safety gating.

## Outputs

- `adapters/worker-local` `WorkerDispatchPort` implementation.
- `ExecutionDriverPort` contract usage + `FakeDriver` in `packages/testkit`.
- `RuntimeSafetyGateLive` (retries, repeated fingerprints, recursion depth, no-progress turns, concurrency ceilings).
- `ExecutionRuntime` orchestration: after durable admission + lease, invoke the driver and persist the returned settlement via `SettleExecution` (ExecutionOrigin, fenced).

## Must Hold

- Dispatch is a durable wake intent; it never acquires a lease; a dispatch failure never settles.
- The driver returns a settlement proposal; persistence is via `SettleExecution`.
- Safety `Stop` → driver returns `Interrupted(RuntimeSafetyStop(reason))`; Work remains Open; Attention emitted.
- Safety never auto-cancels Work.

## Must Not Decide

- No real Provider / Agent loop (P3).
- No tool runtime (P4).
- No settlement bypassing the command pipeline.

## Acceptance

- FakeDriver produces each deterministic settlement kind.
- Repeated action fingerprints trigger `Stop` at the gate.
- Dispatch never mutates Execution state.
- The runtime persists the driver's proposal only through the command pipeline.
