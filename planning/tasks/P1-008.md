# P1-008 — Consumer offset + dead-letter + journal boundary

## Source

- `docs/design/implementation/P1/05-event-journal.md` §3–§6
- `docs/design/implementation/P1/02-port-contracts.md` §3
- DID v1.6 §5.4, §9.9

## Depends On

- P1-006 (`DomainEventJournal`)

## Objective

Implement the consumer cursor, poison quarantine, and the apply-then-advance
projection boundary.

## Outputs

- `ConsumerOffsetStore` (`read` → 0 when absent, `advance` upsert).
- `ProjectionStore` in-DB test projection (`apply`, `reset`) + rebuild per 05 §6.
- `ConsumerDeadLetterStore.quarantine` (`INSERT OR IGNORE`).
- A consumer runner applying a batch and advancing the offset in the same
  transaction, with poison skip.

## Must Hold

- Offset advance and projection write share one transaction (apply-then-advance).
- Poison event → dead-letter + offset advanced past that sequence, same tx; no
  head-of-line stall.
- Re-apply key `(project_id, sequence)`; consumers idempotent.
- `eventVersion` forward-tolerant; no upcasting in v1.
- Projection failure never rolls back the domain transaction.

## Must Not Decide

- No external projection stores.
- No projection query models (P10).
- No new event types.

## Acceptance

- Fresh consumer offset read = 0.
- Poison event quarantined and skipped; consumer continues.
- Crash between projection and commit re-delivers and re-applies safely.
- Batch offset advances to last processed-or-quarantined sequence.
- Rebuild: refuse if offset < pruned floor, reset, replay (05 §6).
- Single-flight per `(consumer_id, project_id)`.
