# P0-008 — Work aggregate & lifecycle

## Source

- DID §3.3 Work
- DID §1.3 Workspace / Work / Execution separation
- DID §12.11 C10 — Work truth table
- DID §3.6 Acceptance / Deliverable / Dependency revision binding
- DID §14.5 criteria 3, 4, 6

## Depends On

- P0-005 (Project)
- P0-006 (Workspace)
- P0-011 (`Verification`, `VerificationMission`)
- P0-012 (`Acceptance`)

## Objective

Implement the pure `Work` aggregate state model and its lifecycle exactly as
frozen in the §12.11 Work truth table.

## Inputs

- `WorkId`, `ProjectId`, `WorkspaceId`, `WorkRevision`.
- `VerificationMission` (from P0-011), `Verification` (from P0-011),
  `Acceptance` (from P0-012).
- `DomainError` union.

## Outputs

- `Work` data type with fields: `workId`, `projectId`, `workspaceId`,
  `objective`, `why`, `constraints`, `completionExpectation`,
  `verificationMission`, `provenance`, `lifecycle: Open | Completed |
  Cancelled`, `revision: WorkRevision`.
- `Provenance` VO (e.g. predecessor / superseded Work reference).
- Pure transitions:
  - `AssignWork` (valid Workspace + authority) → `Open`
  - `RefineWork` / `SteerWork` (authority; producer cannot weaken protected
    upstream requirements) → `Open`, `revision++`
  - `CompleteWork` (current-revision PASS `Verification` + current-revision
    `Acceptance`) → `Completed`
  - `CancelWork` (governance authority) → `Cancelled`
- Pure predicate: is `Work` current for a given `workspace.currentWorkId`.

## Must Hold

- Lifecycle is exactly `Open → Completed` and `Open → Cancelled`.
- `Completed` and `Cancelled` are terminal; any further lifecycle mutation
  is **illegal** and returns a typed error.
- `Current / Pending / Blocked / Verifying / Running` are **not** Work
  lifecycle states.
- `CompleteWork` requires all of: `lifecycle == Open`,
  `verification.workId == work.id`,
  `verification.targetWorkRevision == work.revision`,
  `verification.verdict == Pass`, `acceptance.workId == work.id`,
  `acceptance.targetWorkRevision == work.revision`,
  `acceptance.verificationId == verification.id`.
- A producer cannot weaken `Objective` / `CompletionExpectation` / required
  `VerificationMission`.
- After refine, old `Verification` / `Acceptance` records are not reusable
  for the new revision.
- `Work.workspaceId` is immutable.
- Transitions are pure: `R = never`.

## Must Not Decide

- Do not implement the application-level atomic clearing of
  `workspace.currentWorkId` on complete/cancel; only expose the pure fact
  and precondition (transaction orchestration is P1).
- Do not implement dependency withdrawal or producer-cancel consequences;
  those are `Dependency` transitions owned by P0-012.
- Do not implement execution quiescence; `CancelWork` only records that
  quiescence of the focused active Execution is required.
- Do not add new lifecycle states or a `PromoteWork` operation.

## Acceptance

- Legal and illegal transitions match §12.11 exactly.
- `Completed` / `Cancelled` reversal is rejected with a typed error.
- `CompleteWork` rejects missing / stale-revision / mismatched evidence.
- `WorkLifecycle` is an exhaustive union of exactly `Open | Completed |
  Cancelled` (switch with `never` default); no `Current` / `Pending`
  lifecycle symbol is exported.
- No infrastructure import in the domain package.
