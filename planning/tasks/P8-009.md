# P8-009 — Dual-channel wake wiring (channel-1 release + VerificationReturned routing)

## Source

- P8 `03` §3, `01` §3 (commit boundary); DID v1.11 G2; P7 `06` §2 precedent

## Depends On

- P8-004

## Objective

Verdict wake production in the ConcludeVerification transaction: channel-1
`VerificationChanged` release on any verdict, channel-2 `VerificationReturned`
routing for FAIL/UNKNOWN only.

## Outputs

- Wake production wired into the conclude commit boundary (consumeWakeSignals-family pattern).

## Must Hold

- **Channel 1 — any verdict, including PASS**: scan the target Workspace's Works' active WorkWait; conditions containing `VerificationChanged(workId, targetWorkRevision)` with **exact equality on both fields** (M-1 shape) → release (clear + wake). Satisfaction ⟂ quality: this condition is the only expression of "a concluded verification exists on this Work revision".
- **Channel 2 — FAIL/UNKNOWN only**: wake(workspaceId = owning Workspace of the target Work, reason `{ _tag: "VerificationReturned" }`, detail `{ verificationId, workId, workRevision, verdict }`); Fail → reevaluate (S1 step 9: same Agent reworks, no personnel change); Unknown → reevaluate (evidence/topology; no rework branch — UNKNOWN ≠ FAIL); **PASS never fires channel 2** (acceptance is Parent cognition, not a wake event).
- Wake production shares the ConcludeVerification transaction; no new WakeReason/WakeCondition; payload lives in the delivery record (P7 pattern).
- Refine → revision moves → old waits naturally invalid (DependencyChanged-isomorphic).

## Must Not Decide

- No wake consumption-side changes (P2/P7 wake-sink); no event→Agent-start semantics.

## Acceptance

- Exact-match scan (non-matching workId/revision never released), PASS channel-1-only, FAIL/UNKNOWN dual-channel mechanically checked.
