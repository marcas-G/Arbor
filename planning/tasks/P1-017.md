# P1-017 — Package skeletons + build/test harness wiring

## Source

- DID v1.6 §14.1, §10.1, §10.4.1
- `docs/design/implementation/P1/02-port-contracts.md` §6

## Depends On

- P0-001 (P0 harness)

## Objective

Scaffold the P1 package skeletons and wire the build/test harness, so later
tasks can fill the packages and their tests run.

## Outputs

- Package skeletons (`package.json`, `tsconfig.json`, `src/index.ts`):
  `packages/ports`, `packages/application`,
  `adapters/persistence-sqlite`, `adapters/environment-local`.
- Root `tsconfig.json` project references for those four packages.
- `tsconfig.test.json` includes: `packages/**/src`, `packages/**/test`,
  `adapters/**/src`, `adapters/**/test`, `tests/**`.
- `vitest.config.ts` include globs: `packages/*/test/**/*.test.ts`,
  `adapters/*/test/**/*.test.ts`, `tests/**/*.test.ts`.
- Canonical test-path convention (`<package>/test/<suite>.test.ts`).
- A `p1-harness` test proving a test under `adapters/*/test` is executed.

## Must Hold

- Skeletons make `tsc -b` references resolve before P1-001/P1-002 fill them.
- `pnpm typecheck` compiles every P1 package source and test.
- `pnpm build` builds every P1 package via project references.
- `pnpm test <suite>` matches the suite file (no silent zero-match).

## Must Not Decide

- No domain/port semantics (skeletons are empty).
- No P1 tables, repositories, or command handlers.

## Acceptance

- `pnpm build` / `pnpm typecheck` succeed with empty skeletons.
- `pnpm typecheck` fails on a deliberate type error in `packages/ports`.
- A test under `adapters/*/test` is executed by `pnpm test`.
- `pnpm test p1-harness` matches its file (not zero).

## Verification

```bash
pnpm typecheck
pnpm build
pnpm test p1-harness
pnpm check
```
