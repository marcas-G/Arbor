# P1-017 — Build/test harness wiring + Clock/IdGenerator adapters

## Source

- DID v1.6 §14.1, §10.1, §10.4.1
- `docs/design/implementation/P1/02-port-contracts.md` §4, §6

## Depends On

- P0-001 (P0 harness)

## Objective

Wire the build/test harness so the new P1 packages are compiled and tested,
and implement the `Clock` / `IdGenerator` adapters.

## Outputs

- Root `tsconfig.json` project references for `packages/ports`,
  `packages/application`, `adapters/persistence-sqlite`,
  `adapters/environment-local`.
- `tsconfig.test.json` includes: `packages/**/src`, `packages/**/test`,
  `adapters/**/src`, `adapters/**/test`, `tests/**`.
- `vitest.config.ts` include globs: `packages/*/test/**/*.test.ts`,
  `adapters/*/test/**/*.test.ts`, `tests/**/*.test.ts`.
- Canonical test-path convention (suites under `<package>/test/<suite>.test.ts`).
- `Clock` and `IdGenerator` adapter Layers.

## Must Hold

- `pnpm typecheck` compiles every P1 package source and test.
- `pnpm build` builds every P1 package via project references.
- `pnpm test <suite>` matches the suite file (no silent zero-match).
- `Clock`/`IdGenerator` are deterministic in tests (injected time/entropy).

## Must Not Decide

- No domain/port semantics.
- No P1 tables or repositories.

## Acceptance

- Adding a test under `adapters/*/test` is executed by `pnpm test`.
- `pnpm typecheck` fails on a deliberate type error in `packages/ports`.
- `pnpm build` emits `dist` for each P1 package.
- `Clock`/`IdGenerator` have deterministic test Layers.

## Verification

```bash
pnpm typecheck
pnpm build
pnpm test p1-harness
pnpm check
```
