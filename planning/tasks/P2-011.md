# P2-011 — `SettleExecution` handler

## Source

- P2 `01` §4, §7; `03` §5; DID v1.7 §3.4, §6A.6, G1

## Depends On

- P2-005
- P2-007
- P2-008

## Objective

Implement the `SettleExecution` command handler with the settlement validity rules.

## Outputs

- `SettleExecutionPayload` / `SettleExecutionResult`.
- `makeSettleExecutionHandler` with `SettleExecutionAuthority` and `StopAdmission.QuiescenceControlMutation`.

## Must Hold

- `ExecutionOrigin` path: `expectedFencingGeneration` required; authoritative fence enforced; admissible after stop.
- `RecoveryController` path: recovery authority; no fencing generation.
- Settlement structural validity per `03` §5.2; malformed ADT is a defect.
- `Completed(Yielded)` registers/replaces the durable `WorkWait` in the same transaction and re-reads observed facts.
- `Completed(CompletionClaimed)` persists claimRef + target Work revision.
- Emits `ExecutionSettled`; settle-once.

## Must Not Decide

- No lease operation as a Command.
- No tool/provider reconciliation (P3/P4).

## Acceptance

- Settle once; second settle with a new commandId → `TerminalLifecycleMutation`.
- Stale generation → `FencingRejected`; stopped + valid generation → admitted.
- `Yielded` with empty WaitSpec → defect; `OutcomeUnknown` without refs → defect.
