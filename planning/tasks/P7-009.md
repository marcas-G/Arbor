# P7-009 — Event-driven coordinator (lookup, single command face)

## Source

- P7 `04` §1–§5; DID v1.10 §5.4, G5/G6; SD v1.3 §7.5:795

## Depends On

- P7-005

## Objective

The P7 coordinator: an at-least-once consumer on P1 infrastructure reacting to the frozen trigger set, project-scoped candidate lookup, and `SatisfyDependency` submission with deterministic CommandId and `P7Coordinator` authority.

## Outputs

- Coordinator consumer + `SatisfactionCandidateLookupService` implementation + composition wiring.

## Must Hold

- Trigger set (frozen minimum): `DeliverableProduced` (primary), `DependencyDeclared` / `DependencyContractRevised` (re-check), `DependencyWithdrawn` / `DependencyMarkedUnfulfillable` (idempotent re-check points).
- Correctness property: for every current-and-matching (deliverable, Unsatisfied dependency) pair on the read snapshot, at least one eventual submission; at most one effective — at-least-once redelivery absorbed by the deterministic `CommandId = f(deliverableId, dependencyId, revision)` receipt.
- **Lookup shape not frozen (G5)**: sound (no false pairs, set semantics) + complete (no missed pairs) within the Project are the only frozen properties — scan / index / materialized view all legal; no Project-full-scan contract.
- Coordinator never bypasses the Command Handler — its only mutation face is `SatisfyDependency`; deterministic, no model calls, no AgentId.
- Failures quarantine into P1 `consumer_dead_letters` (same transaction as offset advance); the produce transaction is never blocked; the agent path stays independently available.

## Must Not Decide

- No matcher / algorithm changes; no Message→satisfaction conversion; no cross-Project lookup; no scheduler changes.

## Acceptance

- Auto-satisfaction, replay idempotence (same receipt), matcher-negative leaves state unchanged, dead-letter path — mechanically checked.
