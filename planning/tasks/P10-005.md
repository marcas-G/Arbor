# P10-005 — EffectiveFacts materialization + freshness barrier (GQ2/GQ5; no implicit RYW)

## Source

- P10 `03` 全部; DID v1.13 G2/G5, §1.1 (EffectiveFacts | Projection), §5.4, §8.19; SD v1.3 §3.2

## Depends On

- P10-003

## Objective

The single shared canonical-state-derived projection: materialize
EffectiveFacts (incremental via the generic consumer + on-read derive for
joins), wire the P3 Context Builder to READ it (retiring its own
derivation), and implement the freshness contract — monotonic watermark,
observable lag, explicit barrier — in the query runtime.

## Outputs

- EffectiveFacts snapshot + consumer wiring; P3 Context Builder consumption path; watermark/lag plumbing + barrier runtime; `p10-effectivefacts` suite.

## Must Hold

- Definition inputs **frozen exactly** (`03` §1): Responsibility (current revision) + ResourceBoundary + Workspace policy caps + open Dependencies (state, binding) + current Work + open Verifications + unconsumed Inbox markers — no more, no less.
- **GQ2 single source**: the P3 Context Builder reads this projection and **must not re-derive a second copy**; UI reads the same. P3's own freshness gating for action admission stays per DID §8.19 — unchanged; no P3-side caching contract changes.
- Monotonic watermark: every projection row/read carries the journal sequence it reflects (w); lag = L − w exposed on every query response.
- **Barrier 无 RYW (GQ5)**: queries may pass `FreshnessRequirement {minWatermark}` or `{maxLag}`; the port blocks (bounded catch-up read) or refuses with a **typed staleness marker** when unmet; writers get **no read-your-writes guarantee** — a reader that needs it passes the barrier explicitly (negative test: write then immediate read may lag; barrier forces catch-up).
- Sequence watermark only — no clock-based freshness; no RYW SLA.
- Stale recovery per DID §5.4 (P1 `05` §6, P9-hardened) — reused, not changed.

## Must Not Decide

- No P3 ControlBasis/DecisionStale semantics change; no journal mechanism change; no new EffectiveFacts inputs; no transport.

## Acceptance

- Watermark/lag present on reads; barrier block/refuse paths mechanically checked; no-implicit-RYW negative case green; P3 context-builder reads the projection (single-source assertion — no second derivation path remains).
