# P1-005 — Project / Workspace / Work / Session repositories

## Source

- `docs/design/implementation/P1/02-port-contracts.md` §3
- `docs/design/implementation/P1/04-sqlite-schema.md` §3.1, §3.2
- DID v1.6 §7.3, §3.1–§3.3, §12.11

## Depends On

- P1-003 (DDL)
- P1-004 (transaction)

## Objective

Implement the four canonical repositories as SQLite adapters with CAS
semantics (invariant-oriented, not CRUD).

## Outputs

- `ProjectRepository` (`findById`, `create`, `updatePolicyIfRevision`,
  `closeIfRevision`).
- `WorkspaceRepository` (`findById`, `create`, the CAS mutations,
  `countActiveChildren`, `hasOpenWork`).
- `WorkRepository` (`findById`, `create`, `refine/complete/cancelIfRevision`,
  `listByWorkspace`).
- `SessionRepository` (`findById`, `create`; `appendEntry` is P2).

## Must Hold

- Every method requires `TransactionScope`; no independent connections.
- CAS on `revision` (and revision counters) — mismatch is a typed conflict.
- Project root uniqueness + same-project enforced by the composite FK.
- `parentWorkspaceId` immutable; child inherits project.
- Absence returned as `Option`, not an error.
- Per-repository narrow error type.

## Must Not Decide

- No domain transition logic (delegates to `@arbor/domain`).
- No command handlers.
- No `appendEntry` (P2).

## Acceptance

- Round-trip create/find for each aggregate.
- CAS mismatch rejected; successful CAS increments the right counters.
- Cross-project root/child rejected at COMMIT.
- `pnpm test p1-repositories` and `pnpm check` green.

## Verification

```bash
pnpm test p1-repositories
pnpm check
```
