## Deviations / notes

1. **Transport lives in `apps/single-workspace/src/transport/`.** Contract `10` §2/§5 permits `apps/*` (or a new `apps/<transport>`) and requires daemons to be composition-root wiring rather than new packages (DID §10.4.1). Placing the shells beside the existing composition root avoids a redundant package and keeps `apps/*` as the only transport-owned location; `packages` / `adapters` / `tests` remain transport-free (architecture-asserted).
2. **`packages/application` export additions (enabling change).** The real consumer-loop and drift functions (`pollOnce`, `verificationConsumerLoop`, `completionConsumerLoop`, `probeDrift`) were internal to `application`; the composition root cannot bind them otherwise. Four barrel exports were added. This is additive and changes no semantics; the `application` package DAG (`domain`, `ports`) is unchanged.
3. **P10 boundary guard reconciled (stale phase guard).** `tests/architecture/p10-boundaries.test.ts` carried a pre-P12 negative ("no HTTP/WS/CLI transport anywhere"). P12 now owns that plane (`00` cross-phase table; `10` §1), so the guard is amended to: transport allowed **only** under `apps/<app>/src/transport/`; everywhere else transport-named files and transport imports stay forbidden; `apps/web` stays unbuilt. This is a phase-boundary reconciliation, not a weakening of the P10/P12 boundary.
4. **Composition-root read failures.** `makeRepositoryInputsLoader` treats repository read failures as defects (`Effect.orDie`) — an operational failure at the composition root, not a transport concern. Resolver denial is surfaced as a typed `authority/denied` `Problem` (never a silent default-allow), and gateway operational failures as `command/gateway-failure`.
5. **Daemon binding shape.** `daemons.ts` provides dependency-injected factories plus real bindings (`recoveryDaemonFromPrincipal`, `verificationConsumerDaemon`, `completionConsumerDaemon`, `driftWatcherFromDeps`) and a `makeProductionDaemon` assembler. Concrete slice-layer provisioning remains the composition root's caller responsibility (consistent with the existing `main.ts` `runOnce`, which already runs `startupRecovery`); the daemons introduce no new package and no second mutation face.
6. **Search deferral is a recorded constant, not a surface.** `SEARCH_TRANSPORT_BINDING` records the disposition and `VIEW_IDS` excludes `search`; no query/index semantics are invented. If P10 later freezes a Search view contract, only the transport binding is added.
7. **Remote-worker transport untouched.** `06` owns the authenticated/versioned worker⇄control-plane channel; this task owns only the human/parent shells. The test asserts the human shells carry no worker identity (RG-16). No worker/lease/fencing surface is added.
8. **New dependency.** `@arbor/api-contracts` was added to `apps/single-workspace` (package.json + tsconfig reference + `pnpm-lock.yaml`) to bind the frozen DTO/`Problem` types; `api-contracts` still depends on `domain` only (unchanged).
