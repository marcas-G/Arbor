## Acceptance Evidence

- All seven legal operations match §12.11; each rejects a Retired workspace
  with `TerminalLifecycleMutation`.
- Exported-symbol allowlist: no `ReparentWorkspace`, `MoveWorkspace`,
  `ReactivateRetiredWorkspace`.
- `parentWorkspaceId` is immutable (readonly field; no reparent operation);
  child creation inherits the parent's `projectId`.
- `CurrentWork ≤ 1` (single `currentWorkId` field); candidate must belong to
  the workspace (`AuthorityDenied`) and be `Open` (`WorkNotOpen`).
- `changeResponsibility` increments `responsibilityRevision` + `revision`;
  `updateWorkspacePolicy` increments `revision` + `workspacePolicyRevision`;
  `updateResourceBoundary` increments `resourceBoundaryRevision` + `revision`
  and rejects detected overlap.
- `selectCurrentWork` rejects when an active main execution focuses the old
  current work (`ActiveExecutionConflict`); a `Coordination` focus is allowed.
- `replacePrimarySession` requires a `WorkspacePrimary` target and no active
  main execution.
- `retireWorkspace` enforces every §1.4A precondition, including the
  `ProducerBinding` rule (`WorkspaceBound(this)` / `WorkBound(a Work owned by
  this)`), with `resolvedOrReplacedInSameGovernanceChange` and `AnyProducer`
  exemptions.
- `Workspace.agentBinding` is typed `ResponsibilityBoundAgentBinding`
  (P0-015 cross-task assertion satisfied here).
- No infrastructure import in the domain package.

## Deviations

1. `createWorkspace` (root/bootstrap constructor) is provided alongside
   `createChildWorkspace` so a Workspace can be constructed; only
   `CreateChildWorkspace` is a §12.11 operation.
2. Ownership overlap is taken as an explicit input fact
   (`ownershipOverlapDetected`) computed via the P0-007 pure algebra; the
   rejection uses `AuthorityDenied` with a descriptive reason (P0-004's tag
   set is fixed and has no dedicated ownership tag).
