## Acceptance Evidence

- CAS on `revision` via `UPDATE ... RETURNING`; a stale expected revision
  returns `<Repo>RevisionConflict`; the successful CAS updates policy +
  counters.
- `hasOpenWork` / `countActiveChildren` retire preconditions.
- Every method requires `TransactionScope`; no independent connection.
- `pnpm check`: 28 files, 140 tests.

## Deviations

1. CAS uses `UPDATE ... RETURNING <id>` rather than `SELECT changes()` (Effect
   SQL statement semantics).
2. Repository Layers require `SqlClient | Clock`; timestamps are Clock-sourced
   (02 §6).
3. `Session.entries` / `checkpoints` are not persisted in P1 (their tables are
   P2); reads return empty collections.
