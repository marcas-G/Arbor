## Acceptance Evidence

- Fingerprint stable under key reorder; differs on payload/actor change.
- Same commandId + same fingerprint → existing receipt, handler executed once.
- Same commandId + different fingerprint → `IdempotencyConflict`, existing row
  not overwritten.
- Terminal rejection persists `TerminalRejected` receipt with no event.
- Fence/stop hook evaluated separately for `ExecutionOrigin`; stub distinguishes
  `FencingRejected` from `ExecutionStopping` (inert for External/System).
- `TransactionOperationalFailure` produces no receipt and records a retryable
  attempt in a separate transaction.
