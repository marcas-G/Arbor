## Acceptance Evidence

- Legal transitions match §12.11: `create → Open`;
  `UpdateProjectPolicy → Open` (`revision++`, `projectPolicyRevision++`);
  `CloseProject → Closed` (`revision++` only).
- `Closed` is terminal: both `UpdateProjectPolicy` and `CloseProject` on a
  Closed project return `TerminalLifecycleMutation`.
- `UpdateProjectPolicy` requires authority (`AuthorityDenied`) and expected
  revision (`RevisionConflict` with `expected`/`actual`).
- `Project` has exactly one `rootWorkspaceId`; the field-presence test finds
  exactly one `root*` key, and a `@ts-expect-error` proves omitting
  `rootWorkspaceId` is a type error.
- `Closed` still answers read predicates (`isProjectClosed`), and
  `allowsNewAutonomousExecution` is false for Closed.
- No infrastructure import in the domain package (enforced by P0-017).

## Deviations

1. **Shared `DomainResult` primitive** introduced (needed by pure transitions;
   not listed in P0-005 Outputs). Minimal and semantics-free.
2. **Initial revisions are explicit inputs** to `createProject`
   (`revision`, `projectPolicyRevision`). DID does not fix an initial ordinal
   value, so P0 does not choose one.
