## Deviations / notes

1. **Wire `CommandEnvelope` routing discriminator (contract under-specification).** Contract `06` §6.2 types the wire field as `envelope: CommandEnvelope<unknown>`, but the frozen domain `CommandEnvelope` (DID §4.1) carries no `commandType`, while the control plane routes handlers by it (P12 `02` §2 annotates `CommandEnvelope` as carrying `commandType`). To keep the frozen domain type untouched and avoid a forbidden `ports → application` edge, `ports` declares `WireCommandEnvelope<C> = CommandEnvelope<C> & { readonly commandType: string }` (structurally the application `GatewayEnvelope`). The mediation port passes it to `CommandGateway.execute`. Recorded as a contract under-specification; no `docs/design/**` change.
2. **`ExecutionOrigin` identity carrier (TR-9 mechanism gap).** TR-9 requires `FenceStopCheck` to validate the triple, but the frozen `CommandSubmissionContext.ExecutionOrigin` carried only `executionId` + `fencingGeneration`. Two **optional** fields (`workerId`, `workerIncarnationId`) were added so the authenticated identity can be threaded through the existing gateway call unchanged; production (local and remote) always sets them, and the fence enforces the triple when present. Legacy in-process contexts that omit them remain generation-only. Additive; no DID change.
3. **`appendEntry` fence identity optional.** The fence carries `workerId` / `workerIncarnationId` per TR-9 but marks them optional so legacy in-process callers compile unchanged; the adapter's SQL enforces the full triple when both are present and generation-only otherwise. The production driver threads them from the context.
4. **Principal derivation.** The mediation port derives the authenticated `Principal` from `peer.workerId` (the authenticated worker identity is the principal); the declared `actor` on the envelope is never used as trust input.
5. **Transport error mapping.** `RemoteWorkerTransportPort.submit` fails only with `TransportVersionRejected`; operational `CommandGatewayError`s from the mediation layer do not cross the wire (the composition-root `send` maps them out). The test exercises this mapping.
6. **Migration baseline collateral.** Because migration `0011` alters `execution_leases`, the slice app and every suite that exercises leases now migrate with `P12_MIGRATIONS` (`user_version = 13`). Three test expectations were updated to the current baseline: `p5-composition` (`user_version` 7 → 13), `p5-slice-acceptance` (P8 verification tables are now installed), and `p9-rebuild-durability` (`P12_MIGRATIONS` baseline). `P9_CONSUMER_MIGRATIONS` now aliases the P12 baseline. These are mechanical consequences of the inherited P2 evolution, not new semantics.
7. **Supported wire commands.** The mediation port constructs trusted authority for the `ExecutionOrigin` commands representable by `(executionId, fencingGeneration)` — `SettleExecution` and `StopExecution`; any other command returns `TerminalRejected(AuthorityDenied)` without delegation. Extensible as additional producing planes land.
8. **Migration list (TR-7).** `P12_MIGRATIONS` now declares `{11, lease_worker_incarnation}`, `{12, permission_grants}`, `{13, project_tool_registry}` over the inherited 1–10; `user_version` settles at `max(applied id) = 13`. P12-001's `0013` is not regressed.
