## Deviations / notes

1. **No pre-existing production construction site.** Before P12-012 no production module constructed a `ContextFragment` (only `context.ts` declared the type; test fixtures built literals). The single boundary factory is therefore introduced in `context.ts` (`contextFragment`), and the two P3 test fixtures were migrated to it. No production caller required migration; the required field is compile-enforced (`typecheck` green).
2. **Enforcement shape.** `admitContextTrust` clamps `instructionCapability` from `provenanceKind` (only `CanonicalInternal` may be `CanonicalInstruction`), so a `DataOnly` source cannot forge instruction authority; `canRaiseAuthority` reads the admitted capability. No new trust model or authority ladder was introduced (`13` §7).
3. **Allow-list identity assertion.** The adapters re-export the mechanism from `@arbor/ports` (resolved via `dist`) while the suite imports the ports source module, so cross-instance `toBe` identity is not meaningful; the suite asserts deep equality plus a source scan that each sandbox adapter re-exports (and does not re-declare) the shared allow-list.
4. **Performance declaration placement.** The envelope + measurements + verdict remain owned by `05`; contract `13` only states the declaration, the measurement method, the D5/D6 cross-reference and the DID §13 empirical classification. This record and the suite carry that declaration; no duplicate envelope module was added (avoiding ownership conflict with `05`).
5. **EC-13 naming.** The suite is named `P12-013` (per `14-acceptance.md` §3.1 EC-13) while the task is `P12-012`; both map to contract `13`.
