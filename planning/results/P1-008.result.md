## Acceptance Evidence

- Fresh `ConsumerOffsetStore.read` = 0; `advance` upserts.
- Apply-then-advance in one transaction; a batch applies 2 events and advances
  the offset to the last processed sequence.
- Poison event (`eventVersion > 1`) → `consumer_dead_letters` row + offset
  advanced past it, same tx; the consumer continues (no head-of-line stall).
- Re-apply key `(project_id, sequence)` via `INSERT OR IGNORE`; redelivery is
  idempotent.
- Rebuild: floor = `MIN(sequence)` (0 when none); offset below floor →
  `ConsumerRebuildRefused`; otherwise reset + offset to floor + replay.
- Single-flight relies on `BEGIN IMMEDIATE` + idempotent re-apply.
