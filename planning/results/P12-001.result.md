## Deviations / notes

1. **Migration list (TR-7).** `P12_MIGRATIONS` declares only `0013_project_tool_registry`; `0011_lease_worker_incarnation` (P12-006) and `0012_permission_grants` (P12-002) are owned by their tasks. The forward-only runner keys on `user_version` and applies every migration with `id > current` (sorted), so it does not require a contiguous list; on a fresh DB `user_version` settles at `max(applied id) = 13` (asserted). Owners add their entries by id; the array order is irrelevant to the runner. Recorded in a code comment.
2. **`lookup` transaction scope.** Per the frozen `01` §5.2 signature, `lookup` carries no `TransactionScope`; only `register` does. The adapter captures `SqlClient` at the Layer boundary, so `lookup` has `R = never`.
3. **Typed handler failure.** `ProjectToolRegistryError` is added to `CommandHandlerError`, so the handler propagates the port's typed failure (contract §5.2: "the handler's typed failure"). No error is silently swallowed or converted to a placeholder.
4. **`fingerprintOf` relocation.** Moved byte-for-byte (same `sha256` over the same `fingerprintInputBytes`); the digest recipe and fingerprint semantics are unchanged — **no governance item**. `adapters/environment-resolver-local` now imports it from `@arbor/ports`.
5. **`sandbox-worktree` rejection.** The contract permits "a `ports`-level rejection type (or an adapter-local typed failure)"; chose the adapter-local `SandboxWorktreeCommandRejection` (`{ _tag: string }`), which any command rejection structurally satisfies and which removes the `application` edge without expanding the `ports` surface.
6. **Compatibility policy wiring.** The frozen `RegisterProjectTool` payload is `{ pluginId, pluginVersion, definition, contentHash }` and does not carry `PluginSdkApiVersion`, so `checkPluginSdkCompatibility` is delivered as the pure policy (MAJOR mismatch → `PluginCompatibilityError`) rather than invented into the payload.
7. **`ToolCatalogPort` model-facing wiring.** Registered→catalogued→visible is delivered at the registry layer (`lookup`). The model-facing `ToolCatalogPort` correction is TR-11, owned by P12-007; not touched here.
8. **DID §2.1 id-set test.** `packages/domain/test/ids.test.ts` gains `PluginId` (P12 `01` §2 / G1 evolution), matching the contract's explicit id addition.
