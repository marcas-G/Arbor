## Deviations / notes

1. **`UsageCost` location.** The contract defines the ADT under `04` §3.2 but does not fix its physical home. It is declared in `packages/domain/src/projection.ts` (with `ViewId` / `QueryResult` / `FreshnessRequirement`) so the `api-contracts` `UsageReq` DTO and the `projection-runtime` observability derivation share **one** ADT without a new package edge. `api-contracts` depends only on `domain` (DID §10.4.1; `p10-boundaries` api-contracts-domain-only test still passes). It is a value ADT only — it does not make cost authoritative.
2. **TR-5 wired end-to-end.** Per contract §5 the `UsageReq` row `cost` is the `UsageCost` ADT; the P10 view's hardcoded `0` (P10 result note 4: "Usage cost = 0: no canonical pricing source exists") is replaced with `Unknown` (`PricingUnavailable` for rows with settled turns, `UsageUnavailable` for zero-turn rows) — never `0`. TreeView `usageSummary.cost` uses the same ADT for consistency with the single aggregation source. Affected P10 suites were updated.
3. **`readiness()` return shape.** Per task deliverable 2 / contract §4, `readiness()` returns the `ReadinessState` triple; `ready ⇔ dbOpen ∧ migrationBaseline ∧ t1RecoveryComplete` is exposed as the pure `isReady` predicate (E-17's "readiness() = …"). `PersistenceHealthProbe` is the only capability in its `R` channel.
4. **No persistence adapter shipped.** The task's Outputs scope is the observability module + `ports` `HealthPort`. `PersistenceHealthProbe` is the narrow port interface; the real-DB baseline evidence uses a test-local probe reading `PRAGMA user_version` against `P12_MIGRATIONS`. `P12_MIGRATION_BASELINE` is tied to `max(P12_MIGRATIONS)` by the test.
5. **Module composition.** `observability/usage.ts` + `observability/health.ts` + `observability/index.ts`; no separate physical package (G8 no-empty-shell rule; DID §10.4.1 unchanged).
6. **No telemetry service introduced.** The module exposes no scheduler/admission-reachable service; the boundary suite is the regression guard.
