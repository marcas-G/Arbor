## Deviations / notes

1. **No `PluginSdkApiVersion` bump.** TR-4 classifies add/remove/rename of a
   `ProviderFailureKind` member as a MAJOR SPI change. No member was
   added/removed/renamed here — the six frozen tags and their dispositions are
   unchanged — so the version is not bumped; the rule is encoded mechanically by
   the exhaustive `Record<ProviderFailureKind, …>` (a future member addition
   fails compilation until dispositioned) and by the adapter-boundary
   `ProtocolViolation` normalization.
2. **`ModelCapability` optional fields are additive/MINOR.** `capabilities?` /
   `priceSheetVersion?` are optional; existing consumers remain valid.
3. **New builtin `list` widens the builtin catalog.** Contract `12` §6 adds
   tools through the generic seam; the existing P4/P12-007 suites that asserted
   the exact three-builtin set (`p4-catalog.test.ts`, `p12-toolcatalog.test.ts`)
   were updated to include `list`. No model-facing-resolution semantics changed.
4. **Structural SDK-error guard.** `classifyOpenAISdkFailure` accepts an
   `OpenAISdkError` by class identity or by shape (`name`/`status`/`code`), so the
   translation is robust when the injected client and the adapter resolve
   different copies of the module. The raw value is always discarded.
5. **Composition resolves `modelRef` eagerly.** An unknown `modelRef` or an
   adapter/catalog mismatch throws at composition-build time (deterministic
   config error), never a silent fallback.
6. **`tests/` imports `ports`/`domain` from their built `dist` barrels.** This
   matches the nominal `ProviderPort` service identity used by the composition
   and the adapter `Layer` (same pattern as `tests/p4-integration.test.ts`);
   `pnpm check` runs `typecheck` (which builds) before the test phase.
