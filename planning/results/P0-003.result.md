## Acceptance Evidence

- Ordinal set matches the frozen list (9 entries).
- Round-trip: `parse(WorkRevision)(3) === 3`, `encode === 3`.
- Codec rejects `-1`, `1.5`, `NaN`, `Infinity`, and non-number `"3"`.
- **No starting value is asserted** — DID §2.3 says only "从初始 revision
  开始" and does not fix 0 vs 1, so both 0 and 1 parse and no start is made
  a domain invariant.
- Type-level non-interchangeability: `WorkRevision → DependencyRevision`,
  `LeaseGeneration → ContextEpochNumber`, `EventSequence → EventId`,
  `Actor → Principal` — each `@ts-expect-error` directive is used, so the
  assignments genuinely fail to compile.
- `compareOrdinal` is total (`-1 | 0 | 1`); `incrementOrdinal` is pure
  (`+1`, re-validated by the codec).
- Ordinals are numbers, not prefixed string IDs (no `uuid`/prefix encoding).
- `EventId` (P0-002, branded string) and `EventSequence` (branded number) are
  distinct types.

## Deviations

1. **`Actor` / `Principal` shape.** DID does not define their internal
   structure; implemented as minimal non-empty branded strings. This is a
   value-object primitive choice, not a frozen domain invariant; easily
   relaxed if governance specifies otherwise.
2. **Ordinal codec domain** is non-negative integers. DID does not fix a
   start value; no start is asserted. Negative / fractional / `NaN` /
   `Infinity` are rejected mechanically.

## Scope Discipline

Not implemented (belongs elsewhere): revision increment policy / when to
increment, aggregate transitions, CAS / optimistic locking, SQLite
persistence, lease acquisition, fencing validation, environment resolver,
`ResourceAddress` comparator.
