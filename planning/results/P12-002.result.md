## Deviations / notes

1. **`GrantPermissionAuthority` / `RevokePermissionAuthority` variants (contract under-specification).** Contract `02` §5 declares `GrantPermission` / `RevokePermission` as governance commands and requires the resolver to produce their facts, and DID §4.2 lists the commands, but neither declares an authority variant; the frozen `VerifiedCommandAuthority` union (P1 §2A, extended per phase by P5/P6/P7/P8/P11/P12) had none. Every handler needs a `CommandAuthorityRule`, so the two variants were added **additively** to `VerifiedCommandAuthority` (application-owned). This follows the established per-phase variant pattern (e.g. P12-001's `RegisterProjectToolAuthority`) and is not a `PermissionGrant` type mutation. Recorded here as a contract under-specification (candidate governance/contract-revision item); no `docs/design/**` change was made.
2. **Scope derivation (contract §5 choice (b)).** The frozen P0 `PermissionGrant` carries only `scope: string`; the resolver derives capability/target with the resolver-local grammar `capability["@"targetId]` (`*` = capability wildcard). Documented in `authority-resolver.ts`; the domain type is unchanged.
3. **Envelope typing.** Contract `02` §2 writes `envelope: CommandEnvelope` but annotates it as carrying `commandType`; the domain `CommandEnvelope` has no `commandType`, so the input uses the application `GatewayEnvelope<unknown>` (which has `commandType/commandId/projectId/actor/payload`). No semantic change.
4. **Supported command types.** The resolver produces the explicitly named families: P1 §2A governance (`CreateProject` / `CreateChildWorkspace` / `AssignWork`), `SelectCurrentWorkAuthority` (P5), `RegisterProjectToolAuthority` (P12-001), External `AdmitExecution` / `StopExecution` (TR-8), and `GrantPermission` / `RevokePermission`. Other command types fail typed `UnsupportedOrigin` (never a silent default-allow); the mechanism is extensible as each producing plane lands. `SettleExecution` is not produced (contract §3/§7).
5. **`CanonicalAuthorityFacts` / `ParentUserGovernanceFacts`.** Named but not shaped by contract `02` §2; defined as declared input snapshots (project/workspace/work/execution; authenticated humans + direct-parent edges) consistent with SD §8.1.
6. **Migration list (TR-7).** `P12_MIGRATIONS` now declares `{12, permission_grants}` and `{13, project_tool_registry}` (plus the inherited 1–10); `0011_lease_worker_incarnation` remains P12-006's. The forward-only runner applies by ascending id, so `user_version` settles at `max(applied id) = 13`.
7. **CI-1 caller restriction.** `put`/`revoke` carry `TransactionScope` and are invoked only by the two handlers inside the gateway transaction; the resolver takes grants as a declared snapshot and has `R = never` (source-asserted, no repository reference).
8. **Test domain import.** The suite imports domain types from `../packages/domain/dist/index.js` (not `src`) because `ProjectPolicy` / `WorkspacePolicy` use `unique symbol` brands that are not cross-declaration compatible; this matches the resolver's `@arbor/domain` (dist) types.
