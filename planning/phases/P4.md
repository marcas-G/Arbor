## Goal

Implement the P4 Tool Runtime: `ToolCatalogPort`/`ToolDefinition`,
`ToolRuntimePort` with the frozen SD §6.5 pipeline, trusted
`InvocationAuthority` + capability-ceiling checks, Exact-Intent
`InvocationApproval` with atomic single consumption, validate-only resource
admission, a minimal `SandboxPort`, `tool_invocations` persistence +
`SideEffectSemantics` snapshot + P2 reconciliation, Blob/Artifact service, and
the versioned `read`/`patch`/`shell` tools.

## Included

- `packages/tool-runtime`, `adapters/sandbox-local`, `adapters/blob-local`.
- `packages/ports` P4 contracts.
- `tool_invocations` / `artifacts` / `invocation_approvals` DDL.
- Tool runtime pipeline + `ToolInvocationDenied` projection + bounded observation.
- Versioned `read`/`patch`/`shell` contract artifacts + shell policy enforcement.
- P2 `ReconciliationSource` implementation.
- Integration + architecture tests.

## Excluded

- Advanced sandbox / worktree / git isolation (P11).
- Verification / acceptance (P8).
- Permission/RBAC Authority Resolver (deferred; P4 uses trusted facts).
- Model Context / provider semantics (P3).
- Projection / UI (P10).

## Frozen Decisions (from the P4 contracts)

- Pipeline order is frozen: Intent → Input Validation → Resource Resolution →
  Responsibility Authority → Permission/Approval → Resource Admission →
  Sandbox → Execute → Settlement → Bounded Observation.
- `SideEffectSemantics` drives retry/reconciliation; `NonIdempotent` ambiguity →
  `OutcomeUnknown`, never automatic replay.
- Authority denial → `Denied` observation, never an Execution failure.
- Tool authority is a trusted `InvocationAuthority` fact; P4 does exact-match +
  capability-ceiling only (G1).
- `InvocationApproval` is consumed atomically by exactly one matching invocation (G2).
- Resource admission is validate-only; ownership changes are governance Commands (G4).
- `read`/`patch`/`shell` are versioned contract artifacts; exact schemas and the
  shell policy enforcement mechanism are P4 contract (G5/G6).
- Blob bytes vs Artifact metadata are separate; large output → Artifact reference.

## Must Not Decide

- No PermissionGrant/Parent/User resolver; no default-allow.
- No ownership claim/release; no ResourceBoundary mutation.
- No advanced sandboxing / worktree / git (P11).
- No canonical writes outside `CommandGateway`.
- No Execution settlement policy (P2); no provider retry policy (P3).
- No exact tool allow/deny lists or limit numbers as contract (empirical).

## Exit criteria

P4 is complete when all of:

1. `pnpm check` is green (lint + typecheck + architecture + test).
2. `ToolCatalogPort` + full `ToolDefinition` with exact input/result schemas.
3. `ToolRuntimePort.invoke` implements the frozen SD §6.5 pipeline with
   `Denied` projection and bounded observation.
4. Trusted `InvocationAuthority` exact-match + capability-ceiling; Exact-Intent
   `InvocationApproval` atomic single consumption.
5. Validate-only resource admission using the frozen region algebra.
6. `SandboxPort` + minimal local executor.
7. `tool_invocations` intent-before-effect + `SideEffectSemantics` snapshot +
   P2 `ReconciliationSource`.
8. Blob/Artifact service with bounded observation.
9. Versioned `read`/`patch`/`shell` tools + shell policy enforcement.
10. Architecture tests enforce the P4 package edges.
11. No open P4 Design Gap.
