value objects, aggregate state models, pure transition functions, domain
errors/events, and the invariant + package-DAG test suites — with **no**
SQLite, LLM, Tool, HTTP, or CLI.

## Frozen Decisions (must not be re-litigated in P0)

Lifecycles and terminal rules:

- Project lifecycle `Open | Closed`; `Closed` is terminal and blocks new
  autonomous Execution admission (§3.1, §12.11).
- Workspace lifecycle `Active | Retired`; `Retired` is terminal. The full
  `RetireWorkspace` precondition set applies, including the
  `ProducerBinding`-based incoming-Dependency rule (§1.4A, §12.11).
- Work lifecycle exactly `Open | Completed | Cancelled`; `Completed` and
  `Cancelled` are terminal. `Current / Pending / Blocked / Verifying /
  Running` are relation/projection, never lifecycle states (§3.3, §12.11).
- Execution lifecycle `Absent → Active(settlement = none) →
  Settled(ExecutionSettlement)`; settling a `Settled` Execution is illegal
  (idempotent existing receipt only). Lease/crash/old-worker resurrection
  is not an Execution lifecycle transition (§3.4, §12.11).
- Verification lifecycle `Open → Concluded(verdict)`; re-verification
  creates a new identity (§3.5, §12.11).
- Dependency lifecycle `Unsatisfied | Satisfied | Withdrawn |
  Unfulfillable`; the last three are terminal (§1.8, §12.11).
- PermissionGrant lifecycle `Active | Revoked`; `Revoked` is terminal
  (§12.11).

Structure and binding:

- Workspace `parentWorkspaceId` is immutable; no `ReparentWorkspace` /
  `MoveWorkspace` / `ReactivateRetiredWorkspace` (§1.2, §1.4A, §12.11).
- `CreateProject` atomically creates Project + Root Workspace + Primary
  Session; exactly one Root Workspace per Project (§1.2, §12.11).
- `Agent` is not a long-lived Domain Entity; there is **no** `AgentId`
  (§1.6, §2.1, §14.5 item 13).
- `CurrentWorkId <= 1`; current Work must belong to the Workspace; its
  clearing on complete/cancel is application-level atomicity (§3.2, §12.11).
- `ExecutionSettlement` is a discriminated union; arbitrary
  `outcome × result` combinations are unconstructable (§3.4, §12.2).
- Execution admission-time binding (`executionId`, `projectId`, `binding`,
  `sessionId`, `admittedAt`) is fixed; `execution.sessionId` is immutable
  after admission (§3.4, §12.7).
- Verification verdict is exactly `PASS | FAIL | UNKNOWN`; concluded
  verdict is immutable (§3.5, §14.5 item 8).
- `CompleteWork` requires current-revision PASS Verification **and**
  current-revision Acceptance (§3.6, §12.11).
- A producer cannot weaken `Objective` / `CompletionExpectation` /
  required `VerificationMission` (§3.3, §12.11).
- `Workspace.agentBinding` is `ResponsibilityBoundAgentBinding`;
  `ExecutionBoundAgentBinding` is Execution-scoped only (§1.6, §3.2).
- Dependency producer is `ProducerBinding`
  (`AnyProducer | WorkspaceBound | WorkBound`); `ExpectedDeliverable` is
  `{ kind, requiredArtifactRoles }` and contains no producer; satisfaction
  is the deterministic structural matcher `matchesExpectedDeliverable`
  (§1.8, §3.7).
- `WorkRevision` / `DependencyRevision` are scoped ordinals, not entity IDs
  (§2.3).
- `projectPolicyRevision` / `workspacePolicyRevision` are distinct from the
  aggregate `revision`; only policy-semantic changes increment them
  (§3.1, §3.2, §12.11).
- Canonical architecture-test location is `tests/architecture/**`; no
  second architecture-test root (§10.1, §10.4.1).

Semantics and purity:

- §6A.1 categories are distinct: a normal outcome is not an error;
  `Blocked != Failed`; Execution failure is not Work cancellation;
  `Verification.Unknown` and unresolved Dependency are not failures
  (§6A.1, §6A.11, §6A.14).
- `FailureDisposition` is exactly the 8 frozen variants
  (`ReturnToCaller`, `RetrySameLogicalCommand`, `RetryWithBackoff`,
  `WaitForStateChange`, `ReconcileBeforeRetry`, `SettleExecutionFailed`,
  `SettleExecutionOutcomeUnknown`, `EscalateAttention`); applying it is
  Runtime (P1+) (§6A.3).
- Canonical write ownership overlap is decided on `CanonicalResourceRegion`
  within the same `resourceSpaceId`; cross-space defaults to non-overlap;
  read visibility may overlap, formal write ownership does not (§1.5, §12.9).
- `ResourceOwnershipClaim ⊆ ResourceBoundary` and
  `ResourceBoundary.basisResponsibilityRevision == responsibilityRevision`
  (§4.1A).
- Immutable durable records: `Deliverable`, `Acceptance`, concluded
  `Verification`, terminal `Dependency`, `DomainEvent` (§12.11).
- Command resolution is `Committed(result) | TerminalRejected(typedError)`;
  terminal rejection produces no Domain Event; a same-payload retry after a
  terminal resolution returns the existing receipt; `CommandAttempt` is a
  `(commandId, attemptNo)` local ordinal (§4.1).
- Same `CommandId` + different `semanticRequestFingerprint` →
  `IdempotencyConflict`; a semantic change requires a new `CommandId`
  (§4.1).
- Domain is pure: `R = never` in domain transitions; no infrastructure
  imports in `domain` (§10.3, §10.4).

## Must Not Decide

The implementation agent MUST NOT:

- introduce `AgentId`, `RootWorkspaceId`, or `PrimarySessionId` as entity
  types (Root/Primary are relation roles);
- introduce new lifecycle states for any aggregate (Project, Workspace,
  Work, Execution, Verification, Dependency, PermissionGrant);
- introduce Workspace reparenting or relocation;
- merge Session state with Workspace/Work canonical truth;
- merge `ResourceBoundary`, `ResourceOwnershipClaim`, and `Permission`;
- model `Unknown` / `Blocked` as errors, or let Execution failure change
  Work lifecycle (§6A.1, §6A.11, §6A.14);
- add an `ArborError` catch-all or a global `AppEnv` / service locator;
- add a mutable lifecycle to an immutable durable record;
- infer persistence, transaction, recovery, fencing, or idempotency
  behavior beyond what P0 pure logic can express;
- modify `docs/design/**`.

## Exit criteria

P0 is complete only when all of §14.5 hold:

1. `@arbor/domain` compiles.
2. Typed IDs cannot be crossed at compile time.
3. Core aggregate transitions are pure functions / typed results covering
   §12.11 truth tables.
4. Work terminal lifecycle has no illegal reversal.
5. Parent is immutable.
6. `CurrentWork ≤ 1` holds as domain semantics.
7. `ResponsibilityDefinition / ResourceBoundary / ResourceAddress /
   CanonicalResourceRegion` codecs and pure overlap algebra hold.
8. Verification verdict ADT is fixed to `PASS / FAIL / UNKNOWN`.
9. Execution Binding ADT supports Work / Coordination and `ExecutionBound`.
10. `ExecutionSettlement` is a legal sum type; illegal outcome/result
    combinations are unconstructable at the type level.
11. `Acceptance / Deliverable / Dependency` revision-binding value
    objects/records are expressible.
12. `CommandId / semanticRequestFingerprint / CommandResolution /
    CommandAttempt` base ADTs are expressible, and same-id
    different-fingerprint is rejected by type/pure logic.
13. No long-lived `Agent` Entity / `AgentId`.
14. §10.4.1 package DAG architecture tests pass.
15. `pnpm check` is fully green.

P0 does **not** require SQLite, a real Provider, a real Tool, or HTTP/CLI.
C2/C4/C5 persistence atomicity is implemented in P1 via
adapter/integration tests.
