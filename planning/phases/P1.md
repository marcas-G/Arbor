## Goal

Implement the P1 Persistence + Command Core: SQLite adapter + schema,
`TransactionScope`/`TransactionPort`, P1 repositories, command
logical-request/attempt/receipt persistence, `DomainEventJournal`, and the
`CreateProject` / `CreateChildWorkspace` / `AssignWork` commands with atomic
State + Receipt + Event + authoritative fence hook.

## Included

- `adapters/persistence-sqlite`: connection settings, migrations, DDL.
- `packages/ports`: Effect service contracts (repositories, CommandStore,
  DomainEventJournal, ConsumerOffsetStore/DeadLetter, EnvironmentRevisionStore,
  TransactionPort/Scope, Clock, IdGenerator, ProjectEnvironmentPort).
- `packages/application`: `CommandGateway`, fingerprint, P1 command handlers.
- `ports`: `ProjectionStore`, `OwnershipWriteService` (02 §3).
- `adapters/environment-local`: `ProjectEnvironmentPort` resolver.
- Idempotency/replay, concurrent-duplicate, poison-event, recovery tests.
- Architecture tests for the new packages.

## Excluded

- Execution/lease/fencing runtime (P2); Provider/Tool/Model Context (P3+).
- Non-P1 commands; projections/UI (P10).
- External projection stores.

## Frozen Decisions (from the P1 contracts)

- One semantic command = one transaction (`BEGIN IMMEDIATE`); no durable
  `Pending`; `commands.resolution ∈ {Committed, TerminalRejected}`.
- `CommandResolution<Result, Rejection>`;
  `CommandRejection = DomainError | FencingRejected | ExecutionStopping | WorkspaceNotFound`.
- Fingerprint = canonical JSON v1 + SHA-256, `algorithmVersion = 1`; compared
  with `(fingerprint, schema_version, fingerprint_algorithm_version)`.
- Sequence = project-local, durable `project_event_sequences` upsert.
- Fence and stop are two independent predicates (`FencingRejected` ≠
  `ExecutionStopping`).
- `commands` never hard-deleted; `resource_ownership` soft-release
  (`released_at`); `domain_events` append-only before retention horizon.
- Poison event → dead-letter + offset skip (no head-of-line stall).
- All entity IDs are caller-preallocated; handlers never generate IDs.
- No universal `RepositoryError`; per-repository narrow `E`; `R = TransactionScope`.
- Fingerprint input is exactly `{ commandType, projectId, actor, schemaVersion, payload }`.
- P0 artifacts evolved by P1: `CommandResolution<R>` → parameterized; FNV-1a → SHA-256 v1; `assignWork` `RetirePreconditionFailed` → `TerminalLifecycleMutation`.

## Must Not Decide

The implementation agent MUST NOT:

- change frozen DID / P1 contract semantics;
- add commands, tables, lifecycle states, or error tags not in the contracts;
- introduce generic CRUD repositories or a catch-all error;
- add a durable `Pending` command state or a dual-transaction model;
- approximate resource overlap with SQL string prefixes;
- silently expand scope beyond the P1 command set;
- add new Domain Events (especially a Session event);
- treat a caller ID collision as a typed rejection (it is a defect);
- weaken `BEGIN IMMEDIATE` / `synchronous = FULL`;
- blind-retry after an authoritative conflict.

## Exit criteria

P1 is complete when all of:

1. `pnpm check` is green (lint + typecheck + architecture + test).
2. P1 DDL migrates and all P1 repositories/ports are implemented per `02`/`04`.
3. `CommandGateway` implements the `01` pipeline (single tx, fingerprint,
   idempotency, terminal rejection).
4. `CreateProject` / `CreateChildWorkspace` / `AssignWork` match `01`
   payload/result/rejection/event.
5. Idempotency/replay + concurrent-duplicate + recovery matrix tests pass.
6. The fence/stop hook is present and stub-tested (inert for External/System).
7. Architecture tests enforce the new package edges (DID §10.4.1).
8. No open P1 Design Gap.
