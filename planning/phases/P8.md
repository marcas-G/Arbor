## Goal

Close the quality chain: `CompletionClaimed → StartVerification →
Execution-bound Verifier → Evidence → ConcludeVerification(PASS/FAIL/UNKNOWN)
→ AcceptWorkOutcome → CompleteWork`, with exact revision binding, verifier
isolation, deterministic chain consumers on both ends, dual-channel wake,
one-Open-per-revision, orphan-explicit re-drive, owner-snapshot spawn, and
the P9/P14 program contracts with versioned evals.

## Included

- Domain evolution (declared migrations M-1/M-2 + conclusions/enums/events).
- DDL: verifications / verification_executions / verification_evidence / work_acceptances (migration 8) + repositories; M-4 settlement workId.
- Five command handlers + authority facts (verifier-only two; acceptance parent-chain; complete consumer).
- Consumer A (CompletionClaimed→StartVerification, M-4 event enrichment) and Consumer B (WorkOutcomeAccepted→CompleteWork with full re-validation).
- Verifier spawn/drive (M-3 parentExecutionId optional evolution; WorkerDispatch Verifier; owner snapshot; Yield continuity; settle-without-conclude → Attention).
- Dual-channel wake (any verdict → VerificationChanged work-level release; FAIL/UNKNOWN → VerificationReturned).
- P9 Verification Program + P14 Query/Inspection Program v1 (read-only) with D4 dual versioning + eval gates; P6 placeholder mission migration (M-2).
- Acceptance stories A–G; architecture tests; P5/P6/P7 regression guards.

## Excluded

- Environment change production (P11); Attention presentation (P10); recovery hardening (P9); production daemon (P12); Work lifecycle semantics changes; scheduler decision-table changes.

## Frozen Decisions (from the P8 contracts / DID v1.11)

- Structured mission criteria + required-qualified aggregation (G1).
- Work-level VerificationChanged wait; one Open per (workId, targetWorkRevision) (G2).
- Both chain ends are deterministic consumers; CompleteWork re-validates all bindings (G3).
- Owner snapshot; retirement/move never auto-aborts (G4).
- Orphan re-drive only via explicit Unknown(Orphaned) conclusion then new identity (G5).
- P14 owned here, read-only, P10/P12 consume only (G6).
- PASS never re-judged FAIL; Verifier never mutates Producer results (three-layer enforcement).

## Must Not Decide

- No verdict/aggregation/truth-table changes beyond v1.11; no new WakeCondition/WakeReason; no P7 satisfaction coupling; no evidence domain events.

## Exit criteria

P8 is complete when all of:

1. `pnpm check` green.
2. Migration surfaces M-1–M-4 landed with P2/P3/P1/P6 regression updates green.
3. Five commands enforce frozen rejection sets; one-Open typed rejection; acceptance double-uniqueness idempotency.
4. Story A end-to-end chain closes with binding assertions; PASS also releases channel-1 wake.
5. Story B/C: FAIL returns to the same Producer context; UNKNOWN is first-class (no auto-PASS, no FAIL semantics).
6. Story D: refine invalidates old verification/acceptance; re-acceptance rejected on stale revision.
7. Story E: structured mission enforcement; placeholder mission migration; deliverable revision consistency; environment binding when executable.
8. Story F: program gates (hash/tamper/version); P14 read-only negative.
9. Story G: owner snapshot; no auto-abort on retirement; orphan flow via Unknown(Orphaned) + new identity.
10. Architecture tests enforce P8 placement; consumers never bypass the gateway.
11. No open P8 Design Gap.
