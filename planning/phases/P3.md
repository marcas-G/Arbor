## Goal

Implement the P3 Provider + Model Context + Minimal Agent Loop: the
`ProviderPort`/`ProviderRuntime` with a frozen `CanonicalProviderEvent` ADT,
`ModelCapabilityPort`, Model Context v1 (`prepareTurn`, instruction
fragments/resolver, C0–C6 layers, retention/budget, Skills surface, Compaction
ProviderTurn protocol, `ModelContextManifest`), the real `ExecutionDriverPort`
with `AgentDirective` decode and Output Contract validation, bounded
`ModelOutputContractViolation` repair, `DecisionStale` freshness, and the
shared behavioral-eval harness.

## Included

- `packages/model-context`, `packages/provider-runtime`, `adapters/provider-fake`.
- `packages/ports` P3 contracts.
- `packages/agent-runtime` real control loop over the P2 `ExecutionDriverPort`.
- Versioned Prompt Program contract artifacts (Base Agent Protocol,
  Responsibility-bound Protocol, Work Execution Program, Compaction).
- Behavioral-eval harness + P3 eval cases.
- P3 DDL (`provider_turns`, `provider_attempts`, `model_context_manifests`).
- Integration + architecture tests.

## Excluded

- Tool runtime / sandbox (P4).
- Verification / acceptance (P8).
- Responsibility formation / bootstrap / handoff (P6).
- Dependency/deliverable coordination (P7).
- Live multi-provider support and production hardening (P12).
- Prompt Program text owned by feature phases (P6/P8/…).

## Frozen Decisions (from the P3 contracts)

- `CanonicalProviderEvent` is normalized transport/runtime vocabulary and
  **never** directly expresses an `AgentDirective` (C4).
- `prepareTurn` A = `Ready | NeedsCompaction | GovernanceBlocked`;
  `ContextUnsatisfiable` is typed E.
- Instruction precedence is `Authority > Specificity > Composition > Text
  order`; `A0`–`A3` cannot be overridden.
- P3 owns the Skill surface/loading/provenance/disclosure contract (C1) and the
  explicit Compaction ProviderTurn protocol (C2); P2 keeps Session persistence.
- Prompt Program actual text is a **versioned contract artifact** with
  regression eval (C5); only non-contract wording and numeric defaults are
  empirical.
- P3 provides the real `ExecutionDriverPort`; P2 owns execution-wide Runtime
  Safety gating (DID v1.7 G4).
- P3 establishes the shared behavioral-eval harness (C3); each phase owns its
  own program text/eval cases/acceptance.

## Must Not Decide

- No `AgentDirective` in `CanonicalProviderEvent`.
- No tool authorization/execution (P4).
- No verification verdict/acceptance (P8).
- No Session/Epoch/Checkpoint persistence (P2).
- No canonical writes outside `CommandGateway`.
- No authority-ladder change; no silent context truncation.
- No DID bump; no System Design change.

## Exit criteria

P3 is complete when all of:

1. `pnpm check` is green (lint + typecheck + architecture + test).
2. `ProviderPort`/`ProviderRuntime` implement the frozen `CanonicalProviderEvent`
   ADT; `ModelCapabilityPort` resolves models deterministically.
3. `prepareTurn` returns the frozen A/E; instruction resolution, C0–C6 layers,
   retention/budget and `ContextUnsatisfiable` behave per `02`.
4. Skills surface + progressive disclosure and the Compaction ProviderTurn
   protocol match `02` §7/§9.
5. The real `ExecutionDriverPort` runs the control loop, decodes
   `AgentDirective`s, validates Output Contracts, and calls the P2 safety gate.
6. Bounded `ModelOutputContractViolation` repair and `DecisionStale` freshness
   behave per `06`.
7. The behavioral-eval harness runs P3 program suites deterministically.
8. Architecture tests enforce the P3 package edges (DID §10.4.1).
9. No open P3 Design Gap.
